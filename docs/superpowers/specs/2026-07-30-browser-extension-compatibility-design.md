## 目标

HstarA 在不修改 Chrome 商店插件的前提下，提供稳定、受限、可测试的本地兼容桥，使插件能够：

1. 连接运行中的 Hstar 服务并读取公开的 API 平台列表。
2. 将网页采集的图片和视频批量导入 Hstar 本地素材库。
3. 在用户开启智能分类时，使用所选平台、模型和提示词执行现有分类流程。
4. 在插件未来升级为 `1.8.0` 或更高版本且仍保持现有路由和必需字段语义时，无需按版本修改 Hstar。

兼容性的判断依据是固定插件身份与稳定协议族，不是插件版本号。Hstar 不读取或分支判断 `1.7.0`、`1.8.0` 等版本字符串。

## 非目标

- 不复制、修改或重新分发 Chrome 商店插件源码。
- 不把插件的悬浮采集工具栏移植到 Hstar 页面；该界面和网页扫描能力由插件自身负责。
- 不把插件的文字采集 JSON 自动导入素材库。当前插件文字模式仍按其既有行为下载 JSON。
- 不承诺自动兼容改变路由、HTTP 方法、必需字段名称或响应基本语义的破坏性插件升级。
- 不建立 `5000 -> 3000` 端口代理，也不停止、重启、检查或修改 `D:\Hstar` 稳定安装版及其用户数据。
- 不借本功能重构 Hstar 全局鉴权、全局 CORS 或全部下载逻辑。

## 已确认的插件协议

### 连接与平台读取

```http
GET /api/providers
Origin: chrome-extension://ajfhnbklbmpfaaookhfakohabnpmlcic
```

响应继续使用 Hstar 当前公开结构：

```json
{
  "providers": []
}
```

平台对象必须来自 `public_api_providers()` 或等价的脱敏投影。不得返回 API Key、存储目录或其他私密配置。

### 素材导入

```http
POST /api/local-assets/import-urls
Content-Type: application/json
Origin: chrome-extension://ajfhnbklbmpfaaookhfakohabnpmlcic
```

插件 `1.7.0` 当前请求字段为：

```json
{
  "folder": "网页采集",
  "classify": true,
  "provider": "provider-id",
  "model": "model-id",
  "prompt": "可选分类要求",
  "items": [
    {
      "url": "https://example.com/image.png",
      "name": "image.png",
      "data": "可选的 data URL 或 Base64",
      "content_type": "可选 MIME 类型"
    }
  ]
}
```

响应保留插件已经使用的字段：

```json
{
  "ok": true,
  "count": 1,
  "files": ["网页采集/up_xxx_image.png"],
  "items": [
    {
      "ok": true,
      "file": "网页采集/up_xxx_image.png",
      "item": {}
    }
  ]
}
```

`items` 与请求顺序一致。可增加 `index`、`error_code`、`error`、`warning_code` 等可选诊断字段，但不得删除或改变上述既有字段的含义。

## 架构

### 1. 独立兼容桥

新增独立的 `browser_extension_bridge.py`，负责：

- 固定插件 Origin、允许的路由和 HTTP 方法。
- 预检请求与桥接请求身份判断。
- 宽进严出的插件请求适配。
- 插件响应的稳定投影和错误代码归一化。
- 桥接资源限制与并发控制。

`main.py` 只保留路由挂载、Hstar 领域函数注入和桌面壳会话的桥接豁免，不继续累积插件专用判断。素材存储、平台读取和分类仍由 Hstar 现有领域能力拥有。

### 2. 通用安全远程下载器

从 OpenShop 艺术字体现有的安全远程图片实现中提取通用下载能力，形成独立、可复用、无 OpenShop 文案耦合的模块。OpenShop 与插件导入分别传入自己的媒体类型、字节上限、超时和错误映射。

下载器必须：

- 只接受无用户名和密码的 `http`、`https` URL。
- 对每次 DNS 解析结果拒绝环回、私网、链路本地、保留、多播和其他非全局地址。
- 将连接固定到已验证 IP，同时保留原 Host 与 HTTPS SNI，防止 DNS 重绑定。
- 最多跟随 3 次重定向，并对每一跳重新执行 URL 与 DNS 安全验证。
- 流式写入目标数据根目录中的临时文件，不把远程视频整体读入内存。
- 同时检查 `Content-Length`、实际读取字节数、声明 MIME、扩展名和可识别文件魔数。
- 不使用可能绕过地址固定的系统代理。
- 失败、取消或超时后只删除本次请求创建的临时文件。

一次插件操作只产生一次导入 POST。桥不执行应用级隐藏重试。对同一 DNS 结果尝试最多两个已验证地址以及处理协议重定向，属于一次远程取回过程，不会重复提交素材或分类任务。

### 3. 领域写入适配器

桥接层把合法插件请求转换为 Hstar 的本地素材导入命令。文件命名、文件夹约束、素材元数据、分类旁车和素材库返回对象仍遵守当前 Hstar 规则，避免形成第二套素材库。

## 身份与 CORS

插件无需持有桌面壳密钥，但必须同时满足以下条件：

1. 请求客户端地址是 IPv4 或 IPv6 环回地址。
2. 请求 Host 是当前 Hstar 本地服务的环回主机名或环回字面地址。
3. `Origin` 精确等于 `chrome-extension://ajfhnbklbmpfaaookhfakohabnpmlcic`。
4. 路由与方法精确属于允许集合：
   - `GET /api/providers`
   - `POST /api/local-assets/import-urls`
   - 上述请求对应的 `OPTIONS` 预检

缺失 Origin、伪造插件 ID、非环回来源、未知路由或错误方法均不得绕过桌面壳会话。插件身份只授予这两个最小能力，不获得画布、设置、文件系统或关闭软件等其他 API 权限。

桥接响应的 `Access-Control-Allow-Origin` 必须是固定插件 Origin，不得为 `*`；允许方法和请求头也只覆盖实际协议。现有全局 CORS 行为可在本任务外保持不变，但不得覆盖桥接响应的精确 CORS，也不得提前吞掉桥接预检。契约测试必须验证最终 HTTP 响应头，而不只测试辅助判断函数。

CORS 不是唯一身份边界。即使浏览器未执行 CORS，后端仍通过 Origin、环回与路由白名单拒绝不合法请求。

## 前向兼容规则

桥采用“兼容新增，拒绝歧义”的解析策略：

- 顶层和单项对象中的未知新增字段被忽略，不导致失败。
- 缺失的可选字段使用稳定默认值：`folder="网页采集"`、`classify=false`、`provider="comfly"`、`model=""`、`prompt=""`、`name=""`、`content_type=""`。
- 已知字段必须保持预期类型；例如 `items` 必须是数组，`classify` 必须是布尔值，文本字段必须是字符串。不得把复杂对象静默转为字符串。
- 每个素材项必须具有一个可用来源。非空 `data` 优先，且不得同时再次下载 `url`；没有 `data` 时，`url` 必须是安全的 `http` 或 `https` URL。
- 空批次、超过上限、缺失来源或不安全类型明确失败，不猜测新语义。
- 响应可以增加字段，但保留 `ok`、`count`、`files`、`items` 的既有语义。

因此，未来插件仅增加元数据、可选控制项或响应读取逻辑时可以自动兼容；如果未来版本改名或删除必需字段、改用新路由或改变素材来源语义，Hstar 返回明确协议错误，需要经过一次新的设计评估。

## 批量与原子性语义

一次 POST 是一个批次，但不是全有或全无事务：

1. 在写入前完成身份、Content-Type、请求体大小、顶层 Schema、项目数、目标文件夹和存储写入屏障检查。
2. 以上任一检查失败时，整个请求拒绝且不创建目标文件夹、素材文件或分类旁车。
3. 合法批次中的素材逐项处理。单项失败只在对应结果中记录，不回滚已成功素材。
4. 每个素材先写入与最终文件同卷、同数据根的唯一临时文件，完成字节、类型和路径检查后使用原子替换提交。
5. 目标文件名使用现有 UUID 前缀与安全名称规则，不覆盖同名旧素材。
6. 目标文件夹延迟到首个可提交素材时创建。
7. 图片提交成功后再执行可选 AI 分类。分类失败不删除、不覆盖素材；该项保持导入成功，并返回分类警告。
8. 分类旁车也使用临时文件加原子替换，避免半写 JSON。

批次中至少一个素材成功时，HTTP 为 `200`、`ok=true`。合法批次全部单项失败时仍返回 HTTP `200`，但 `ok=false`、`count=0`，并在每项中提供稳定错误代码。这样插件可以显示成功和失败数量，同时保留已经写入的素材。

## 初始资源限制

所有限制集中定义在桥接模块，不散落在路由中。初始默认值为：

| 资源 | 默认限制 |
|---|---:|
| 单批素材项 | 200 |
| JSON 请求体 | 256 MiB |
| 单项内联解码内容 | 64 MiB |
| 整批内联解码内容 | 192 MiB |
| 单张远程图片 | 64 MiB |
| 单个远程视频 | 2 GiB |
| 整批远程落盘内容 | 8 GiB |
| 并发远程下载 | 4 |
| 并发 AI 分类 | 2 |
| DNS 解析 | 3 秒 |
| 建连 | 20 秒 |
| 网络空闲读取 | 30 秒 |
| 单项总时限 | 10 分钟 |
| 重定向 | 3 次 |
| 单主机候选地址尝试 | 2 个 |

若剩余磁盘空间不足以保留 1 GiB 或卷容量的 5%（取较大者），新素材在提交前失败为 `insufficient_storage`。服务繁忙时使用有界工作队列并返回可诊断的 `busy`，不得无限创建任务。

任何上限调整必须更新契约测试和发布说明；不得依据插件版本号改变限制。

## 错误模型

请求级错误在任何素材写入前返回非 `2xx`：

| 场景 | HTTP | 稳定错误代码 |
|---|---:|---|
| 非法或缺失插件身份 | 403 | `extension_forbidden` |
| 路由或方法不允许 | 403/405 | `extension_route_forbidden` |
| JSON、Schema 或必需语义错误 | 400/422 | `invalid_import_request` |
| 请求体或项目数超限 | 413 | `import_limit_exceeded` |
| 存储切换屏障阻止写入 | 409 | `storage_switch_in_progress` |
| 服务工作队列已满 | 429 | `bridge_busy` |
| 当前存储不可用 | 503 | `storage_unavailable` |

单项错误放在 HTTP `200` 的 `items[index]` 中，包括 `unsafe_url`、`dns_failed`、`remote_timeout`、`remote_http_error`、`unsupported_media`、`item_too_large`、`invalid_base64`、`insufficient_storage` 和 `commit_failed`。面向插件的错误文本简短可读，日志使用稳定错误代码。

任何错误都不得返回异常堆栈、API Key、完整本地路径或桌面壳令牌。

## 存储与用户数据保护

- 导入只写入当前活动数据根的本地素材目录。
- 不扫描、不迁移、不合并其他数据根，也不访问稳定安装版数据。
- 导入请求受现有 `STORAGE_WRITE_BARRIER` 保护。存储切换已经进入只读阶段时，请求在写入前失败；已获得写入租约的批次完成后才允许切换。
- 路径解析后必须再次使用 `realpath/commonpath` 验证目标仍位于当前素材根目录，防止目录穿越与链接逃逸。
- 清理逻辑只持有本请求创建的临时路径集合，不按通配符删除目录内容。

## 日志与隐私

每个批次只记录：请求 ID、结果计数、错误代码分布、处理字节数分段、耗时和插件协议族。不得记录：

- 完整素材 URL 或其查询参数。
- Base64、Data URL 或网页文字内容。
- API Key、认证头、桌面壳令牌。
- 完整本地目录、用户名或自定义存储根。
- 用户分类提示词全文。

必要时可记录经单向摘要处理的主机名以关联重复故障，但默认关闭。

## 本地 `1.0.2` 插件的处理

Chrome 商店固定 ID 插件是本功能唯一支持和发布验证的浏览器插件。仓库中的 `tools/chrome-local-asset-importer` 视为历史开发工具：

- 不打包到 Windows 安装包，不作为用户安装入口，不继续增加与 Hstar 的自动发现或端口切换逻辑。
- 实施前逐项审查当前未提交差异。仅清理能够证明属于已放弃 `1.0.2` 适配路径的新增连接模块、测试和说明；不覆盖同一文件中的其他用户改动。
- 若历史工具仍被其他测试或开发流程引用，则保留其基线功能并明确标记为不受支持，而不是直接删除整个目录。

- 文件名与文件夹目录穿越、符号链接逃逸、畸形 Base64 和伪造 MIME。

### 真实工作流

1. 工程版：在不接管 `5000` 的前提下启动 HstarA `127.0.0.1:3000`，插件配置一次 `3000`，验证连接、平台列表、图片/视频扫描与导入。

## 构建与发布

- `browser_extension_bridge.py`、通用安全下载模块及其依赖必须进入自包含桌面发布和安装包 stage。
- 发布 stage 必须从当前源码重新构建，不复用旧 stage；校验脚本需要断言桥接模块、固定插件 ID、白名单路由和默认 `5000` 配置均存在。
- 工程版默认 `3000` 与发行版默认 `5000` 分别测试，二者不互相代理。
- 安装包测试必须使用隔离安装和数据目录，不停止或覆盖当前稳定安装。
- 只有用户再次明确要求打包时才生成新的安装包。

## 验收标准

设计完成后的实现必须同时满足：

1. 未修改 Chrome 商店插件文件，`1.7.0` 能连接 HstarA 并导入所选图片和视频。
2. 模拟仅增加未知可选字段的未来版本请求无需代码分支即可工作。
3. 非固定插件、非环回来源和非白名单 API 无法借桥接身份访问 Hstar。
4. 远程下载无法访问本机、局域网、云元数据地址或通过 DNS/重定向绕过限制。
5. 大批量处理受项目数、字节、并发、超时和磁盘余量约束，服务不会无限占用内存或任务。
6. 每项原子写入，部分失败不破坏成功素材；请求级失败不产生素材或残留临时文件。
7. 分类失败不删除素材，不触发隐藏重试，不泄露用户配置。
8. 工程版 `3000` 与隔离发行版 `5000` 的真实插件流程均通过。
