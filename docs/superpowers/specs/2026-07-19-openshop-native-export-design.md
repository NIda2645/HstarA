# OpenShop 原生导出与发送成功提示设计

## 1. 目标

为 HstarA 内嵌 OpenShop 增加统一的本地保存体验：

- 在宿主顶栏“发送到画布”左侧增加“下载到本地”按钮。
- 顶栏按钮默认按文档原始尺寸导出当前可见图层的 PNG 合成结果。
- 文件菜单中的 PNG、JPEG、WebP、SVG、PDF、PSD 均使用 Windows 原生“另存为”窗口。
- 批量导出只选择一次文件夹，再保存所有勾选格式。
- “发送到画布”只有在目标图片节点创建并且画布数据保存成功后，才显示简短成功提示。

本功能不得改变文档尺寸、裁切范围、图层数据或 OpenShop 后台任务生命周期。

## 2. 方案选择

采用统一原生保存管线：OpenShop 在编辑器内生成目标格式文件，调用主画布已经使用的 `/api/native/save-output-as` 或 `/api/native/save-output-batch`，由后端打开 Windows 保存窗口并写入用户选择的位置。

不采用以下方案：

- `<a download>` 或仅使用浏览器 `showSaveFilePicker`：与主画布行为不一致，且不同运行环境表现不同。
- 先上传项目资产再保存：会产生不必要的项目文件和网络/磁盘往返。

## 3. 用户界面

### 3.1 顶栏按钮

OpenShop 宿主顶栏操作顺序调整为：

1. 来源更新
2. 保存
3. 下载到本地
4. 发送到画布

“下载到本地”使用下载图标和文字，视觉规格沿用现有宿主命令按钮。点击后：

- 按当前文档原始宽高生成 PNG。
- 仅包含当前可见图层的最终合成画面。
- 不包含编辑器边界、选框、控制点、参考线或其他 UI。
- 保留 PNG 透明区域。
- 弹出 Windows 原生“另存为”窗口。

按钮在导出请求进行中禁用，避免重复弹出多个系统窗口；完成、取消或失败后恢复。

### 3.2 文件菜单导出

“导出为”下所有格式都进入同一原生保存管线：

- PNG：无损、保留透明度。
- JPEG：质量沿用当前设置，透明区域使用白色背景。
- WebP：沿用当前质量设置并保留支持的透明度。
- SVG：使用清理后的 SVG 内容。
- PDF：使用当前文档宽高生成单页 PDF。
- PSD：保留现有 PSD 图层生成结构。

所有格式都以当前文档坐标系和原始宽高为导出边界。JPEG 的白色背景只存在于导出副本中；SVG、PDF 和 PSD 同样不得按当前缩放视口重新取样或改变文档尺寸。

导出设置窗口的最终导出动作也使用原生保存窗口。

### 3.3 批量导出

用户确认批量导出后：

1. OpenShop 先在内存中生成全部勾选格式。
2. 任一格式生成失败时停止，不打开文件夹选择器，也不写入部分文件。
3. 全部生成成功后只弹出一次 Windows 文件夹选择窗口。
4. 后端使用安全文件名和自动冲突编号保存全部文件，已有同名文件不会被覆盖。
5. 用户取消时不写入文件、不显示错误。

## 4. 导出架构

### 4.1 编辑器导出产物

在 OpenShop 核心中建立统一的异步导出入口，返回：

```js
{
  blob,
  filename,
  mimeType,
  format,
  width,
  height,
}
```

PNG、JPEG、WebP 共用同一画布合成路径；SVG、PDF、PSD 分别复用现有编码逻辑，但不再直接触发浏览器下载。所有路径必须在 `finally` 中恢复 Fabric viewport、边界对象属性和临时可见性，取消或异常不得改变编辑状态。

### 4.2 原生保存客户端

单文件保存：

- 将 Blob 转成不含 Data URL 前缀的 Base64 正文。
- 读取 `hstar.outputDownloadFolder` 作为初始目录。
- 调用 `/api/native/save-output-as`，传入 `content_base64`、建议文件名和初始目录。
- 用户在系统窗口确认已有同名文件时允许覆盖；用户取消时返回明确的取消状态，不作为错误处理。
- 仅在文件写入成功后更新最近保存目录。

批量保存：

- 扩展 `/api/native/save-output-batch` 的 `items`，同时接受现有 `url` 和新的 `content_base64`。
- 每个内存产物以 `{ name, content_base64 }` 传递；`content_base64` 同样不含 Data URL 前缀。
- 后端在打开文件夹选择窗口前校验全部项目的文件名和 Base64 内容；校验失败时不创建任何文件。
- 后端保持现有文件名清理、冲突编号和最近目录持久化逻辑，并且仅在批量写入成功后更新最近目录。

后端保存对话框根据建议文件扩展名显示对应过滤器，至少覆盖 PNG、JPEG、WebP、SVG、PDF、PSD，并保留“所有文件”。

## 5. 宿主协议

OpenShop 协议增加：

- `REQUEST_DOWNLOAD_LOCAL`：宿主请求编辑器按 PNG 导出到本地，携带本次唯一 `requestId`、`format: "png"` 和现有作用域字段。
- `DOWNLOAD_LOCAL_RESULT`：编辑器返回相同 `requestId`、现有作用域字段以及 `status: "success" | "cancelled" | "error"`；成功时携带实际文件名，失败时携带经过清理的错误信息。

宿主只通过协议调用编辑器，不直接访问 iframe 内部 `OS` 对象。宿主同一时间只保留一个待完成下载请求；结果消息必须同时匹配 `requestId` 以及现有 session、project、canvas 和 node 作用域。旧会话、其他节点、重复结果或已被后续请求取代的迟到结果不得改变当前按钮状态或显示提示。

文件菜单直接调用同一个编辑器导出入口，因此顶栏按钮和菜单不会形成两套实现。

## 6. 发送到画布成功回执

现有流程中，宿主收到 `SEND_TO_CANVAS` 后只代表输出已转发给来源画布，并不代表图片节点已经创建成功。因此增加真实完成回执：

1. 宿主收到 `SEND_TO_CANVAS` 后创建唯一 `requestId`，将其同时记录为待确认请求并附加到转发给来源画布的输出消息。
2. 普通画布或智能画布创建图片节点、建立连接并完成 `saveCanvas()`。
3. 画布 iframe 向宿主发送 `hstar-openshop-output-applied`，包含原 `requestId`、作用域和新节点 ID。
4. 宿主验证消息来源、作用域和待确认请求后，显示约两秒“已发送到画布”。
5. 导入或 `saveCanvas()` 失败时发送带有同一 `requestId` 的失败回执；宿主显示简短错误，不显示成功提示。

重复回执、未知请求、其他节点或其他画布的回执必须忽略。

## 7. 提示与错误处理

- 本地保存成功：`已保存：<文件名>`。
- 发送成功：`已发送到画布`。
- 用户取消：静默结束。
- 编码失败、原生窗口失败或文件写入失败：显示经过长度限制和字符清理的错误。
- 提示使用宿主顶栏之下的轻量临时消息，不使用需要确认的模态窗口。
- 提示不得遮挡顶栏按钮或右侧图层面板。

## 8. 安全与性能

- 保持后端文件名清理；单文件保存沿用 Windows 覆盖确认，批量保存使用冲突编号且不覆盖已有文件。
- 仅允许同源、本机 Hstar 页面调用原生保存接口。
- Base64 在请求完成后立即释放，不写入项目 JSON、历史记录或 localStorage。
- 高分辨率导出不得使用缩略图或视口尺寸，始终使用文档原始尺寸。
- 保存期间不暂停 OpenShop 后台生成、文字提取或艺术字体任务。

## 9. 测试

### 9.1 单元测试

- 协议识别两个新增消息类型，并拒绝未知、`requestId` 不匹配或跨作用域消息。
- PNG/JPEG/WebP 导出保持原始尺寸并恢复 viewport 与边界状态。
- SVG/PDF/PSD 生成 Blob，不触发 `<a download>`。
- 单文件保存发送无 Data URL 前缀的正确 Base64、文件名和最近目录。
- 取消保存不提示成功，失败提示错误。
- 批量保存只调用一次文件夹选择接口，携带所有勾选格式，并对同名文件使用冲突编号。
- 宿主按钮在请求期间禁用，迟到结果不能修改新会话。
- 普通和智能画布只有在 `saveCanvas()` 成功后发送完成回执。

### 9.2 浏览器测试

- 顶栏按钮位于“发送到画布”左侧，桌面和窄窗口均无重叠。
- 点击顶部按钮会触发原生保存 API，取消后界面可继续操作。
- 文件菜单各格式走原生保存 API。
- 批量导出一次选择目录并保存全部格式。
- 普通画布和智能画布发送成功后均显示短提示，失败时不显示成功提示。

## 10. 验收标准

1. 顶栏“下载到本地”默认以当前文档原始尺寸保存 PNG。
2. 文件菜单 PNG、JPEG、WebP、SVG、PDF、PSD 均弹出 Windows 原生保存窗口。
3. 批量导出只弹出一次文件夹选择窗口。
4. 用户取消不产生文件、不显示错误。
5. 所有导出不裁切、不缩放、不改变当前编辑状态。
6. “已发送到画布”只在目标节点创建并持久化成功后出现。
7. 普通画布、智能画布和 OpenShop 现有保存、后台任务、项目隔离行为保持通过。
