# HstarA 工程版 E2E 测试画布清理设计

## 目标

OpenShop/HstarA 工程版浏览器测试创建的画布只用于当前测试。测试成功、失败或中途抛错后，都必须永久删除画布及其关联 OpenShop 项目和临时资源，不进入 30 天回收站，也不保留到下一轮测试。

稳定安装版的数据不属于本机制的访问范围。

## 方案

新增一个仅供 Playwright 测试使用的共享清理器：

1. 每次 `POST /api/canvases` 成功后，立即把响应中的画布 ID 登记到当前测试文件的内存集合。
2. `test.afterEach` 使用同一个 `request` 和 `HSTAR_BASE_URL`，逐个调用 `DELETE /api/canvases/{id}/purge`。
3. 清理器只接受本轮测试创建后登记的精确 ID，不支持按标题、前缀、时间或目录扫描删除。
4. 即使后续 `PUT`、页面操作或断言失败，已登记 ID 仍会进入 `afterEach` 清理。
5. 清理失败时测试必须失败并报告具体 ID，不能静默遗留数据。

## 数据隔离

- 清理请求只发送到测试已经使用的 `HSTAR_BASE_URL`。
- 只能删除由同一测试进程收到的创建响应 ID，因此不会命中服务中原有画布。
- 不读取、不扫描、不修改稳定安装版的画布目录。
- 不提供全局“删除所有 E2E 标题画布”的常驻逻辑，避免名称碰撞导致误删。

## 接入范围

当前会创建 HstarA 画布的测试文件全部接入共享清理器：

- `hstar-canvas-integration.e2e.spec.js`
- `hstar-text-tools.e2e.spec.js`
- `hstar-generative-tools.e2e.spec.js`

只操作 OpenShop 页面、但不调用 `POST /api/canvases` 的测试无需接入。

## 历史遗留数据

历史测试画布采用一次性审计清理：

1. 从工程服务读取候选测试画布。
2. 验证每个候选 ID 对应文件位于当前 worktree 的 `data/canvases`。
3. 输出并审核精确 ID 清单。
4. 仅对审核后的 ID 调用工程服务 `/purge`。
5. 再次查询工程服务和 worktree 文件，确认候选均已消失。

此一次性流程不写入产品代码，也不访问稳定安装版目录。

## 验证

- 单元测试覆盖登记、成功清理、失败报告和重复清理。
- 运行三组会创建画布的 E2E 测试，结束后比较工程服务画布 ID 集合，确认没有新增测试画布残留。
- 验证非测试画布 ID 在清理前后保持不变。
