# Hstar Windows 11 启动壳、关闭确认与首次储存向导设计

日期：2026-07-28
状态：已确认

## 1. 背景

当前 Windows 11 安装版缺少从桌面窗口出现到主功能真正可操作之间的加载动画，右上角关闭按钮原有的二次确认也已消失。现有 Windows 11 桌面壳只有编译产物，没有在 HstarA 仓库中保留可维护源码，导致启动和窗口生命周期行为无法稳定迭代。

本设计恢复一套进入版本管理的 Windows 11 x64 桌面壳，在同一个软件窗口中提供完整启动覆盖层、可靠的可交互就绪判定、关闭确认和首次数据位置向导。安装包继续以完整功能、启动效率和离线可运行性为优先，不通过删除必要运行时、模型组件或原生依赖来追求体积。

## 2. 目标

- 软件窗口出现后立即显示本地启动画面，不出现白屏、空白页或 CMD 窗口。
- 启动画面持续到主页面真正可以点击操作，而不是在后端仅返回 HTTP 200 时提前结束。
- 使用用户指定的 React Bits Lightfall 视觉算法和配置。
- 使用灰金属色粗体的“Hstar 正在启动中”扫光文字。
- 在文字左侧加入用户提供的一大两小三星标志，并与文字同步扫光。
- 三星标志和文字作为一个整体，在启动区域水平、垂直双向居中。
- 恢复右上角关闭、Alt+F4 和任务栏关闭的统一确认弹窗。
- 首次安装后的第一次启动显示美化的数据目录向导，默认预选 `E:\Hstar缓存`。
- 数据位置切换只切换读取和写入根目录，不自动迁移、清空或覆盖其他目录的数据。
- 将桌面壳源码、启动资源、构建脚本和测试全部纳入 HstarA 仓库。
- 保持工程版 3000 端口、D 盘稳定版和 `E:\Hstar缓存` 在开发及测试阶段不受影响。

## 3. 非目标

- 不修改普通画布、智能画布、OpenShop 或 3D 导演台的业务功能。
- 不重新设计 Hstar 主页面导航和业务页面视觉。
- 不合并 Windows 11 版与经典兼容版安装包。
- 不在本工作中迁移任何现有用户数据。
- 不把安装位置当作用户业务数据位置。
- 不为减小安装包体积裁剪无法充分验证的依赖。

## 4. 已确认的总体方案

采用同一软件窗口内的双层 WebView2 结构：

1. 顶层启动 WebView2 立即加载完全本地化的 Lightfall 启动页。
2. 下层主 WebView2 与 Python 后端并行初始化。
3. 两个 WebView2 共享同一 `CoreWebView2Environment` 和用户数据目录，避免建立两套长期运行环境。
4. 主页面发送明确的 `hstar:interactive` 消息后，桌面壳淡出并销毁启动层。
5. 主页面接管同一个软件窗口，不创建第二个主窗口。

启动层是临时资源。淡出完成后必须解除事件监听、取消动画帧、释放 WebGL 上下文并销毁顶层 WebView2。主页面长期运行期间不保留重复的启动渲染进程。

## 6. 启动生命周期

### 6.1 首帧

桌面窗口先以不透明深色背景显示。标题栏、窗口尺寸和深色底不依赖 WebView2 完成初始化，因此即使 WebView2 首次创建需要数百毫秒，也不会出现白色闪屏。

桌面壳随后并行执行：

- 创建共享 WebView2 环境；
- 加载本地启动资源；
- 解析首次启动和数据目录状态；
- 在已有有效数据目录时启动 Python 后端；
- 预创建主 WebView2。

### 6.2 普通启动

已有有效数据目录时，Lightfall 始终保持在最上层。后端健康检查成功后，下层主 WebView2 导航到本次启动的本机地址。主页面在以下条件全部满足后发送 `hstar:interactive`：

- DOM 已完成初始化；
- 关键样式和本地脚本已加载；
- 左侧导航和页面切换事件已绑定；
- 默认首页已经渲染；
- 关键设置、画布入口和桌面桥已可调用；
- 不存在阻止主页面操作的全屏错误状态。

桌面壳只接受来自预期本机源、当前导航代次和当前 WebView2 实例的消息。收到有效消息后立即执行约 220 毫秒淡出，不设置人为最低展示时长。

### 6.3 就绪协议

主页面向桌面壳发送：

```json
{
  "type": "hstar:interactive",
  "schemaVersion": 1,
  "navigationId": "<current-navigation-id>"
}
```

桌面壳在每次导航时生成新的 `navigationId` 并通过初始化脚本注入。旧导航、子框架或未知来源的消息不能关闭启动层。

### 6.4 超时和失败

启动协调器使用明确状态机：

```text
WindowVisible -> StartupVisualReady -> BackendStarting -> MainLoading
-> MainInteractive -> StartupVisualDisposed
```

失败终态包括：

- 数据目录无效；
- 后端启动失败或提前退出；
- 健康检查超时；
- 主页面导航失败；
- 主页面未在限时内发出可交互消息；
- WebView2 初始化失败。

失败后不无限播放动画。原窗口显示“重试启动”和“退出 Hstar”。重试只重建失败的后端和主页面代次，不重复创建桌面进程。日志写入用户数据根目录的可再生日志区；若数据根目录尚未确定，则写入 `%LocalAppData%\Hstar\logs`。

故障超时采用明确上限：WebView2 环境初始化 15 秒、后端健康检查 45 秒、主页面完成导航后等待 `hstar:interactive` 30 秒。任一阶段进入下一状态后重置对应计时器，重试会生成新的导航代次和独立计时器。

## 7. Lightfall 启动视觉

Lightfall 使用用户提供的 OGL Shader 源码，转换为桌面壳本地启动页可直接执行的模块。React 包装层只负责生命周期，视觉算法不变；桌面壳不为了一个短暂启动页额外启动完整 React 和 Motion 运行时。

确认的参数为：

```js
{
  colors: ['#8eb6f9', '#644f9a', '#1d1717'],
  backgroundColor: '#0A29FF',
  speed: 0.5,
  streakCount: 2,
  streakWidth: 1,
  streakLength: 1,
  glow: 1,
  density: 0.6,
  twinkle: 1,
  zoom: 3,
  backgroundGlow: 0,
  opacity: 1,
  mouseInteraction: true,
  mouseStrength: 0.2,
  mouseRadius: 1
}
```

颜色以用户提供的 Lightfall 配置网址中的 `color1`、`color2`、`color3` 为最终可见色板。所有资源随软件安装，不访问 React Bits、CDN 或其他远程地址。

### 7.1 文字和三星标志

- 显示文字固定为 `Hstar 正在启动中`。
- 字重为 800，使用中性灰金属色，不使用暖金或发黄高光。
- 基础色使用枪灰和钢灰，高光使用冷银白。
- 扫光方向从右向左，约 2 秒一轮，无停顿、无悬停暂停。
- 三星标志采用用户参考图的一大两小四角星轮廓，生成透明单色本地遮罩资源。
- 三星标志和文字共享同一个渐变进度，保证高光同步经过两者。
- 整个“图标 + 文字”组合按外接矩形在启动区域双向居中。

`prefers-reduced-motion` 或 Windows 减少动画设置启用时，Lightfall 使用静态首帧，文字和标志保留稳定灰金属渐变，不持续扫光。

## 8. 首次数据位置向导

### 8.1 出现条件

桌面壳在启动后端前读取 `%LocalAppData%\Hstar\bootstrap.json`。该文件只保存启动所需的数据根目录指针和结构版本，不保存画布、素材、输出、API 配置或其他业务数据。

以下情况显示向导：

- 文件不存在；
- 文件结构损坏；
- 未设置数据根目录；
- 设置的磁盘或目录当前不可访问。

正常升级和重新安装必须保留有效指针，不重复显示首次向导。

### 8.2 默认路径

默认候选按以下顺序解析：

1. `E:\Hstar缓存`；
2. E 盘不存在时使用 `D:\Hstar缓存`；
3. E、D 均不可用时使用当前用户“文档”目录下的 `Hstar缓存`。

界面始终显示最终实际路径，不声称一个不存在的磁盘可用。

### 8.3 界面

采用已确认的单页聚焦式布局：

- 顶部显示 Hstar 和“首次设置”；
- 标题为“选择 Hstar 数据位置”；
- 路径输入框默认填入解析后的候选；
- “选择文件夹”打开系统原生文件夹选择器；
- 路径下方内联显示“位置可用”“确认后自动创建”“发现已有 Hstar 数据”或具体错误；
- 主按钮为“开始使用 Hstar”；
- 次要按钮为“退出”；
- 使用 Windows 系统浅色或深色主题；
- 中央内容列使用稳定宽度，适配高 DPI 和窄窗口，不使用嵌套卡片。

### 8.4 数据语义

- 选择任意空目录或非空目录都允许继续。
- 选择已有 Hstar 数据目录时按兼容协议直接读取。
- 选择普通非空目录时，Hstar 只在其中创建和维护自己的固定子目录及清单。
- 选择新目录时，只在用户点击“开始使用 Hstar”后创建目录。
- 不从之前位置复制、移动、合并或删除数据。
- 返回旧位置时继续读取该位置原有数据。
- 路径确认后，桌面壳原子写入启动指针，并通过环境变量把数据根目录传给后端。
- 后端必须优先使用桌面壳传入的数据根目录，不在启动中擅自回落到 C 盘业务目录。

首次向导完成后，同一窗口重新显示 Lightfall，启动后端并进入普通启动流程。

## 9. 软件设置中的数据位置

首次向导和“软件设置”必须共用同一套路径规范化与验证规则。现有页面中“正在迁移数据”“已迁移并保存”等旧文案和旧迁移调用必须移除。

软件设置中的变更流程保持已确认语义：

1. 用户选择新位置并点击保存；
2. 弹出“是否确认重启 Hstar”；
3. 用户取消时恢复变更前路径，不改启动指针，当前画布继续运行；
4. 用户确认时原子更新启动指针并执行受控重启；
5. 新进程直接使用新位置，不迁移旧位置数据。

工程版 HstarA 的现有数据根目录配置保持独立。开发和测试不得把工程版业务数据切换到 `%LocalAppData%`。

## 10. 关闭确认与受控重启

桌面壳统一拦截：

- 自定义或原生标题栏右上角关闭；
- `Alt+F4`；
- 任务栏窗口关闭命令。

确认弹窗内容：

- 标题：`确认关闭 Hstar？`
- 正文：`关闭后，正在运行的任务将停止。`
- 按钮：`取消`、`关闭 Hstar`
- 默认焦点：`取消`

`Esc` 取消关闭。重复触发只保持一个弹窗。确认后先请求后端优雅停止并等待最多 5 秒，再结束仍存活的受管进程树。整个过程不得显示控制台窗口。

以下场景不重复弹出关闭确认：

- 用户已经在数据位置变更弹窗中确认自动重启；
- 应用内部明确发起的受控升级重启；
- Windows 正在注销或关机。

受控重启使用桌面壳自身重启机制，不再生成可见批处理窗口。普通关闭和受控重启必须通过显式枚举状态区分，不能依赖易失的布尔值竞态。

## 11. 桌面桥与安全边界

- 本地启动页通过 WebView2 虚拟主机或内存资源映射加载，不使用可变远程内容。
- 启动页设置严格 CSP，只允许本地脚本、样式和 WebGL。
- 桌面桥只向主顶层页面暴露必要方法。
- 文件夹选择返回规范化绝对路径，不把任意文件系统操作暴露给网页。
- 关闭、重启和路径写入由桌面壳执行，网页只能发出结构化请求。
- 所有桌面消息包含 `schemaVersion` 和导航代次，并验证来源。

## 12. 安装包与依赖策略

Windows 11 安装包继续独立于经典兼容版。构建必须：

- 发布 Windows 11 x64 桌面壳；
- 保留完整、经过验证的 .NET、WebView2、Python、语音助手、OpenShop 和现有功能运行依赖；
- 包含 Lightfall、OGL、三星资源和所有启动页资源；
- 保留安装目录选择页；
- 使用指定 Hstar 品牌图标；
- 保留“是否覆盖 API 配置”勾选框；
- 保留用户数据根目录启动指针；
- 不覆盖用户选择的数据目录；
- 使用新版本号和新安装包文件名，不覆盖现有 R2 安装包。

允许常规压缩和确定无风险的重复文件清理。禁止使用未经完整验证的程序集裁剪、原生 DLL 删除、模型组件删除或运行时按需下载。安装包体积不是验收指标。

## 14. 完成标准

1. Windows 11 桌面壳源码和构建脚本已进入 HstarA 版本管理。
2. 从窗口出现到主页面真正可操作之间始终有正确的 Lightfall 启动画面。
3. 灰金属三星标志与粗体文字居中并同步动画。
4. 启动失败不会无限等待，并能重试或退出。
5. 所有关闭入口恢复确认弹窗，取消和确认语义正确。
6. 首次安装显示已确认的单页数据位置向导。

8. 数据位置切换不迁移数据，取消重启不改变位置。
9. 安装包完整保留必要依赖、安装位置选择、品牌图标和 API 覆盖选项。
10. 性能、视觉、隔离、全量回归和安装测试全部通过。
