# Hstar 储存位置确认与自动重启设计

## 目标

软件设置中的“自定义储存”在用户保存新目录前必须进行重启确认。确认发生在任何目录创建、写权限探测、bootstrap 更新或储存切换请求之前。

- 用户取消时，Hstar 保持当前储存根目录和运行状态不变。
- 用户确认时，Hstar 才直接切换到所选目录，并自动完成受控重启。
- Windows 安装版和 `3000` 端口开发版都必须支持自动重启。
- 切换仍遵守直接使用目标目录、不迁移数据、不改动原目录和目标目录无关文件的既有契约。

## 用户交互

### 保存前确认

用户选择目标目录 `X` 并点击“保存”后，设置页先比较 `X` 与当前活动目录 `Y`。

- `X` 与 `Y` 相同时，不显示确认弹窗、不调用切换接口、不重启，只提示“当前已使用该储存位置”。
- `X` 与 `Y` 不同时，显示自定义确认弹窗。
- 弹窗明确显示目标目录，并提示：确认后将切换储存位置并自动重启 Hstar；原目录数据不会被迁移、删除或修改。

弹窗提供“取消”和“确认”两个命令。弹窗使用设置页现有颜色变量适配白天和黑夜模式，并支持键盘焦点管理及 `Esc` 取消。

### 取消

点击“取消”、按 `Esc` 或关闭弹窗均执行相同行为：

1. 不发送 `/api/storage-migrations` 请求。
2. 不创建或探测 `X`。
3. 不修改 bootstrap、`Y` 或 `X`。
4. 将储存位置输入框恢复为当前活动目录 `Y`。
5. 关闭弹窗，解除界面阻塞，允许继续正常操作画布和其他功能。

### 确认

点击“确认”后：

1. 关闭确认弹窗并禁用储存位置相关控件，防止重复提交。
2. 调用现有 `/api/storage-migrations` 直接切换接口。
3. 后端解析、创建并写权限探测目标目录，随后通过 `switch_storage` 原子更新 bootstrap。
4. 切换任务完成后进入自动重启流程。
5. 新后端健康检查通过且活动储存目录为 `X` 后，恢复 Hstar 操作界面。

## 重启架构

### Windows 安装版

安装版继续使用现有 WebView2 消息 `hstar-restart-with-data-root`：

1. 前端发送已完成切换的目标目录 `X`。
2. 桌面壳释放语音助手、WebView 和画布会话。
3. 桌面壳正常停止旧后端。
4. 桌面壳验证 bootstrap 中的活动目录与 `X` 一致。
5. 桌面壳使用 `X` 启动新后端，等待健康检查通过后重新加载界面。

桌面壳现有来源校验、绝对路径校验、程序目录隔离和防重复重启锁继续保留。

### `3000` 端口开发版

开发版增加受控运行时重启接口和进程内重新执行逻辑：

1. 重启接口只允许 loopback 请求，并且只在 `development` edition 下启用。
2. 请求中的期望目录必须是绝对路径，位于程序目录之外，并与 bootstrap 当前活动目录完全一致。
3. 接口记录待重启目录和当前进程实例编号，然后安排 Uvicorn 正常退出。
4. `run_server()` 返回后，将 `HSTAR_DATA_DIR` 更新为目标目录，并使用同一 Python 运行时、同一程序入口、同一主机和端口重新执行 Hstar。
5. 重新执行不得启动 CMD 窗口，也不得触碰 `5000` 端口或稳定版 Hstar 进程。

开发版重启接口不承担储存切换职责。它只能在 bootstrap 已成功切换后重新启动当前开发进程，避免出现第二条修改储存配置的路径。

## 页面恢复

`/api/health` 增加当前后端实例编号和活动储存根目录。设置页在重启前记录旧实例编号，然后：

1. 显示“正在重新启动 Hstar”遮罩，停止新的写操作。
2. 轮询 `/api/health`，容忍旧服务关闭期间的连接失败。
3. 只有响应来自不同实例，且活动储存根目录等于 `X` 时，才认定重启成功并重新加载页面。
4. 不能仅以一次 HTTP 200 判断成功，避免把尚未退出的旧进程误认为新进程。

安装版由桌面壳完成健康检查和页面重新加载；浏览器开发版由设置页完成实例检测和重新加载。

## 状态与错误处理

- 路径非法、不可写、与当前目录重叠或位于程序目录内：切换失败，不重启，恢复控件并显示后端返回的具体原因。
- 切换请求失败：活动目录继续显示 `Y`，不发送重启请求。
- 切换已经完成但重启请求未成功发出：保留已完成任务状态，显示“重试重启”，重试时不得再次调用储存切换接口。
- 页面等待新实例超时：显示“重新检测”和“重试重启”，停止无限轮询。
- 重启命令重复触发：前端忙状态和桌面壳防重复锁共同保证一次切换只启动一次重启。
- 用户在确认前离开设置页：不产生任何储存变更。

一旦 bootstrap 已完成切换，旧后端继续遵守现有写屏障，不再产生新的业务写入，直至受控重启完成。

## 组件边界

### `static/js/storage-settings-panel.js`

- 保存当前活动目录。
- 比较当前目录与候选目录。
- 管理确认弹窗、取消恢复、切换任务及重启状态。
- 桌面环境发送 WebView2 重启消息。
- 浏览器开发环境调用运行时重启接口并等待新实例。

### `static/software-settings.html`

- 提供储存位置重启确认弹窗。
- 提供重启遮罩、失败提示和重试命令所需元素。
- 使用现有设计变量完成浅色和深色模式适配。

### `main.py`

- 在健康响应中公开非敏感的进程实例编号和活动储存根目录。
- 提供仅限本机 development 版本的受控重启接口。
- 在服务器循环退出后，以切换后的数据根目录重新执行当前开发进程。
- 保持 `/api/storage-migrations` 的直接切换职责不变。

### Windows 桌面壳

- 沿用现有受控重启入口。
- 验证重启请求与已持久化的 bootstrap 结果一致。
- 不允许网页任意指定未经切换验证的数据目录。

## 安全约束

- 确认前不得调用任何会创建、扫描或写入目标目录的接口。
- 重启接口只接受 loopback 请求，安装版仍由 shell session 和 WebView 来源策略保护。
- 目标目录必须与 bootstrap 中已完成的切换结果一致。
- 自动重启不得终止、重启或占用稳定版 `5000` 端口。
- 重启参数不得包含网页提供的任意可执行文件、脚本路径或附加命令。
- `Y`、`X` 的普通文件和旧 Hstar 数据均不得因确认、取消或重启而被复制、删除、重命名或覆盖。

## 测试策略

### 前端 Node 测试

- 保存新路径只打开确认弹窗，尚未发送切换请求。
- 点击取消、按 `Esc` 和关闭弹窗均不发送请求，并恢复输入框为 `Y`。
- 同路径保存不显示弹窗、不切换、不重启。
- 确认后只创建一次 `switch_storage` 任务。
- 完成任务后桌面环境只发送一次受控重启消息。
- 浏览器开发环境只调用一次重启接口，并等待不同实例和正确目录。
- 重启请求失败或等待超时时出现重试操作，重试不重复切换。

### Python 测试

- `/api/health` 返回实例编号和当前活动储存根目录。
- 开发版 loopback 请求可以安排重启。
- 非本机请求、非 development edition、错误目录和未匹配 bootstrap 的目录均被拒绝。
- 服务器退出后重新执行使用相同入口、端口和目标 `HSTAR_DATA_DIR`。
- 原目录和目标目录文件树在切换及重启调度过程中保持不变。

### 桌面端测试

- 有效重启消息调用一次受控重启。
- 外部来源、相对路径、程序目录内路径和与 bootstrap 不匹配的路径继续被拒绝。
- 后端停止、以新目录启动、健康检查及页面恢复顺序保持正确。

### 全量验证

完成实现后运行 Python、Node、OpenShop、桌面端、构建、编码审计、敏感信息审计、静态缓存一致性和 `git diff --check`。最后在隔离目录执行真实 HTTP 切换与开发版自动重启测试，并确认 `Y`、`X` 的原有内容均未变化。

## 非目标

- 不恢复软件设置中的数据复制或迁移功能。
- 不改变语音模型数据目录的独立迁移逻辑。
- 不修改稳定版 Hstar 的缓存、数据和 `5000` 端口进程。
- 不在本功能中重构其他设置项或画布储存协议。
