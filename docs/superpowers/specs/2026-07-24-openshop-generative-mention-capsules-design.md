# OpenShop 生成式工具缩放启动与引用胶囊设计

## 目标

调整 OpenShop 的“生成式填充”和“局部重绘”交互：启动功能时先显示缩放窗口并等待用户新建选区；本次新选区完成后自动展开完整操作面板。同时让两种工具共享 `@` 引用功能，并将已插入的引用显示为输入区内的蓝色胶囊。

## 启动与选区状态

点击任一功能按钮后：

1. 不复用启动前已经存在的旧选区。
2. 清理该功能上一次保存的瞬时选区引用和显示标记。
3. 启用最近使用的选区工具；没有可用记录时启用矩形选框工具。
4. 设置状态为 `selecting`，操作窗口显示为现有缩放样式。
5. 用户完成本次第一个有效新选区后，将状态切换为 `ready`，取消缩放并自动显示完整操作面板。
6. 后续新增选区继续保持完整面板行为，并同步增加缩略图和 `@选区N` 候选。

用户再次点击当前功能按钮关闭功能时，继续沿用现有逻辑：清除该功能创建的选区、引用和操作窗口状态。

## 引用编辑器

现有普通 `textarea` 改为两种工具共用的 `contenteditable` 编辑器。编辑器包含两类内容：

- 普通提示词：可编辑文本节点。
- 引用：`contenteditable="false"` 的蓝色胶囊元素，内部保存稳定的 `assetId`、显示别名和纯文本 mention。

输入 `@` 时，两种工具都打开统一引用候选窗口。选择 `@选区1` 等候选后，删除触发选择器的 `@` 查询文本，在当前光标位置插入胶囊，并在胶囊后保留一个可继续输入的空格。

胶囊作为不可拆分的编辑单元：

- `Backspace` 或 `Delete` 一次删除整颗胶囊。
- 鼠标可以将光标放到胶囊前后，但不能进入胶囊内部修改。
- 粘贴内容按纯文本处理，防止外部 HTML 注入编辑器。
- 重新渲染面板后，根据结构化编辑内容恢复胶囊和光标可编辑状态。

## 数据与 API 契约

编辑器内部维护结构化内容，但对既有系统提供纯文本兼容层：

- 胶囊序列化为自身 mention，例如 `@选区1`。
- 普通文本、换行和胶囊按显示顺序拼接为 `state.prompt`。
- API 请求、任务保存、恢复和日志仍使用现有纯文本 prompt 字段，不修改上游协议。
- 从已有纯文本恢复时，将当前引用管理器能够解析的 mention 转为胶囊；无法解析的 mention 保留为普通文本。

引用以 `assetId` 作为稳定身份，别名只用于显示和序列化。删除缩略图、选区或引用记录时，同步删除编辑器内匹配 `assetId` 的胶囊，避免提交悬空引用。选区重新编号时，同步刷新对应胶囊的显示文本和序列化 mention。

## 组件边界

在 `openshop-generative-tools.js` 内增加聚焦于提示词编辑的局部辅助函数：

- 将结构化编辑内容渲染为安全 DOM。
- 从编辑器 DOM 序列化纯文本 prompt。
- 在当前 Selection/Range 位置插入引用胶囊。
- 处理胶囊级删除、纯文本粘贴和引用同步清理。

引用候选数据继续由 `openshop-reference-manager.js` 提供，不改变引用资产的持久化格式。面板样式仅在 `openshop-generative-tools.css` 增加编辑器和蓝色胶囊状态，不改变当前功能按钮布局。

## 错误处理

- 没有有效新选区时保持缩放等待态，不允许提交生成。
- 引用候选为空时，`@` 选择器显示空状态，不插入无效 token。
- 编辑器失去焦点或面板重渲染前先同步 prompt，避免输入丢失。
- 已删除引用对应的胶囊自动移除，其他提示词保持不变。
- 结构化恢复失败时退回纯文本显示，保证提示词仍可编辑和提交。

## 测试范围

单元测试覆盖：

- 两种工具启动后均为缩放等待态，并忽略旧选区。
- 本次新选区完成后自动恢复完整面板。
- 两种工具输入 `@` 都能打开候选并插入蓝色胶囊。
- 胶囊在光标位置插入，可用 Backspace/Delete 整体删除。
- 胶囊按 mention 正确序列化，普通文字和换行不丢失。
- 删除或重新编号引用后，胶囊同步清理或更新。
- 粘贴外部 HTML 时只保留文本。

浏览器测试覆盖完整用户路径：启动功能、看到缩放窗口、绘制新选区、面板展开、插入引用胶囊、编辑提示词并确认提交数据。测试同时验证生成式填充和局部重绘，不依赖付费生成即可验证本次 UI 与数据契约。
