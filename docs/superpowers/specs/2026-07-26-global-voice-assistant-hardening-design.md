# HstarA 全局语音助手交互与识别加固设计

## 1. 背景与目标

本设计是 `2026-07-26-global-voice-assistant-design.md` 的交互和识别质量补充。现有全局语音链路已经覆盖主页面、智能画布和 OpenShop，并能使用完整的 `FunAudioLLM/Fun-ASR-Nano-2512` 模型真实推理；本轮只修复当前暴露的六类问题，不改变现有页面功能按钮布局，也不把模型或运行时打入安装包。

目标如下：

1. 麦克风入口在白天模式显示为黑底白色麦克风，在黑夜模式显示为近白底黑色麦克风。
2. 入口只绑定当前获得焦点的合格文本目标，随目标移动、缩放和页面生命周期实时更新，不残留在其他功能页面上。
3. 模型已经安装时，点击入口后尽快触发浏览器麦克风授权，不等待模型冷启动完成。
4. 临时和最终识别结果始终从保存的输入位置连续写入，光标保持在最新文字末尾。
5. 降低短暂停顿误断句、白噪音误触发和静音幻觉，同时保留连续 10 秒无有效语音自动关闭。
6. 点击入口不使当前文本目标失焦，不丢失光标或选区。
7. 文字状态提示在 HstarA 自身的白天和黑夜模式中均有稳定对比度。

## 2. 非目标

- 不增加唤醒词、后台常驻录音或云端 ASR 回退。
- 不用通用正则重写模型生成的中文标点。
- 不为主页面、智能画布和 OpenShop 分别创建独立录音服务。
- 不更改语音模型下载、存储、打包排除和 5000 端口稳定软件边界。
- 不在本轮重构与语音生命周期无关的画布模块。

## 3. 方案选择

采用“目标绑定状态机”方案：主壳保留唯一 `VoiceCoordinator`，每个页面继续使用共享 `VoiceTargetAdapter`。适配器拥有目标的焦点、选区和几何状态；协调器拥有唯一录音会话、悬浮入口和服务连接。二者通过带目标 ID 和代次编号的消息同步。

不采用单纯 CSS 和失焦补丁，因为它不能可靠处理嵌套 iframe、画布缩放和过期目标消息；也不采用每页独立协调器，因为那会重复占用麦克风、模型连接和资源清理逻辑。

## 4. 目标生命周期

### 4.1 状态

目标状态独立于录音状态：

```text
无目标 -> 已聚焦 -> 录音启动中 -> 聆听/识别 -> 停止中 -> 已聚焦
   ^         |              页面切换、失焦、目标移除              |
   +---------+-----------------------> 无目标 <------------------+
```

- 合格文本框获得焦点时立即注册为活动目标并显示入口。
- 录音停止但文本框仍有焦点时，入口继续显示并允许再次启动。
- 文本框失焦、页面隐藏、iframe 隐藏或卸载、目标移除时，活动目标立即失效并隐藏入口。
- 目标失效发生在录音期间时，提交已确认文字，取消未确认组合文字，停止会话并释放麦克风。
- 新目标代次建立后，旧目标的异步位置、失焦和识别消息全部丢弃。

### 4.2 iframe 消息

共享适配器使用以下同源消息：

```text
hstar-voice-target-active
hstar-voice-target-geometry
hstar-voice-target-lost
hstar-voice-target-command
```

消息携带 `targetId`、`generation`、`framePath` 和标签。几何消息由目标所在页面在 `scroll`、`resize`、`visualViewport` 变化、`ResizeObserver` 回调和目标激活后发送；连续变化通过 `requestAnimationFrame` 合并。中间 iframe 只补充路径并转发，主协调器使用现有同源目标解析计算最终窗口坐标。

主协调器收到与当前目标匹配的 `lost` 时必须无条件清除该目标，不能因为 DOM 元素仍然存在就继续保留。定位时还需校验目标和各级 iframe 已连接、可见并具有正尺寸；失败即隐藏入口并使目标失效。

## 5. 入口交互与主题

### 5.1 按钮

- 保留现有 `28px` 圆形入口和悬浮布局。
- 白天模式：近黑色圆形底、白色麦克风、暗色阴影。
- 黑夜模式：近白色圆形底、黑色麦克风、清晰边界和暗色阴影。
- 主题判断以 HstarA 的 `theme-dark` 和 `studio-theme-dark` 类为准，`prefers-color-scheme` 只作为应用尚未初始化时的兜底。
- 图标使用现有 Lucide `mic`，初始化失败时提供可见的 CSS/文本降级，不能显示空圆圈。

### 5.2 识别动画

只有收到有效语音并进入 `recognizing` 状态时，按钮外侧出现约 `2px` 的彩虹渐变圆环。圆环使用旋转和轻微呼吸变化，不改变按钮盒模型，不推动周围布局；离开识别状态后立即隐藏。系统开启 `prefers-reduced-motion: reduce` 时显示静态彩虹描边。

### 5.3 状态文字

状态文字使用带底色、边界和阴影的紧凑提示，不直接把文字叠在画布内容上：

- 白天模式：浅色提示底、深色文字。
- 黑夜模式：深色提示底、浅色文字。
- 加载、识别和错误状态保持可见；普通待机状态只在悬停或键盘聚焦入口时显示。
- 提示框限制最大宽度并避免超出视口，不遮挡对应文本框主要输入区域。

## 6. 焦点、选区与文本事务

### 6.1 启动时保持焦点

入口在 `pointerdown` 阶段保存当前目标和选区，并阻止按钮获得文档焦点。随后使用 `focus({preventScroll: true})` 和保存的选区恢复目标，再执行开始或停止命令。由入口自身引起的 `focusout` 不得发送目标失效消息；真正点击其他区域仍按正常失焦处理。

### 6.2 input 与 textarea

事务开始时保存原始值、选区起点和选区终点。每次临时更新都只替换当前组合区间，并在写入后执行：

```text
compositionEnd = start + currentText.length
selectionStart = compositionEnd
selectionEnd = compositionEnd
```

最终提交后仍把选区折叠在最终文字末尾。下一条语句创建新事务时从该位置继续，不能回到首次启动位置。取消事务时恢复启动前的值和选区。

### 6.3 contenteditable 与自定义编辑器

`contenteditable` 使用稳定组合标记保存插入位置。每次更新后在标记末尾重建折叠 `Range`；最终提交时把标记替换为文本节点，并把光标移动到该文本节点末尾。自定义编辑器继续使用现有组合协议，但必须由适配器在每次 `updateComposition` 和 `commitComposition` 后恢复其逻辑末尾选区。

所有写入继续触发现有 `beforeinput`、`input`、自动保存和节点脏状态链路。每条最终结果形成一个撤销单元，临时结果不进入撤销栈。

## 7. 权限与模型启动

启动顺序调整为：

1. 读取轻量状态，确认功能已启用、运行时和模型已安装。
2. 状态确认后，同时启动麦克风授权请求和模型服务冷启动。
3. 两者都成功后建立 AudioWorklet 和 WebSocket，并开始发送音频。
4. 任一分支失败或目标失效时，取消另一分支的后续连接并释放已取得的媒体流。

模型或运行时缺失时仍不申请麦克风权限，而是进入首次安装流程。浏览器已经授予权限后，后续 `getUserMedia` 按浏览器权限策略直接复用，不额外创建 HstarA 自定义授权弹窗。拒绝、设备占用和无设备继续使用现有稳定错误码。

## 8. VAD、断句与幻觉抑制

### 8.1 双重门控

WebRTC VAD 继续作为语音分类器，同时增加轻量 PCM 能量门控：

- 在非语音帧上维护有上限的动态噪声底线。
- 只有 WebRTC VAD 为真且帧能量相对噪声底线达到最小信噪比时，才计为候选语音。
- 候选语音需连续确认约 `120ms` 后才正式启动语句，启动前保留的预卷音频用于防止吞掉首字。
- 低于最短有效时长、整体能量过低或信噪比不足的片段不送入模型，也不重置 10 秒静默计时。

阈值采用具名常量并通过真实音频回归确定，不能散落硬编码在服务逻辑中。

### 8.2 停顿与标点

- 句中 hangover 从当前 `0.7s` 提高到约 `1.3s`，因此约 `0.5s` 的自然停顿仍属于同一语句。
- 继续使用模型原生 ITN 和标点输出，不通过通用字符串替换强制改逗号或句号。
- 最长语句保护仍保留，防止无限缓存；强制切段后的下一段继续在当前光标末尾写入。
- 连续 10 秒没有确认到新语音时，提交已有有效语句、停止录音并释放设备。

### 8.3 文本结果过滤

服务只发送通过音频门控的语句结果。空白结果直接丢弃；完全相同的迟到结果由序列号和当前事务状态丢弃。静音或白噪音产生的低能量短片段不能进入模型，因此不依赖维护脆弱的“幻觉词黑名单”。

## 9. 错误与资源清理

- 页面切换、目标失效、启动取消、权限拒绝、服务断开和 10 秒静默停止都走同一个幂等资源释放路径。
- 资源释放包含媒体轨道、AudioWorklet、AudioContext、WebSocket、未提交事务和目标锁。
- 已提交文字不得因后续错误回滚；未提交临时文字在目标失效或异常断开时取消。
- 服务冷启动与权限请求并行时，任何迟到成功结果都必须检查启动代次，过期媒体流立即停止。
- UI 错误只显示一条中文状态提示，不重复堆叠同义消息。

## 10. 测试策略

### 10.1 前端单元测试

- 文本框聚焦显示入口，失焦和页面隐藏立即隐藏。
- 匹配的 iframe `lost` 即使目标 DOM 仍存在也会清除活动目标。
- iframe 内滚动、窗口缩放、画布缩放和目标尺寸变化会更新入口位置。
- 按钮 `pointerdown` 不改变焦点、光标或选区。
- 多次 partial、final 和下一句 partial 后，光标始终位于最新文字末尾，文字顺序稳定。
- 状态检查完成后，权限请求与服务启动并行；模型缺失时不申请权限。
- HstarA 显式白天/黑夜类覆盖系统主题，按钮、状态文字和提示底色均符合对应配色。

### 10.2 Python 单元测试

- 稳定白噪音、低能量脉冲和不足最短时长的声音不触发识别。
- 正常语音首字不会被确认窗口截断。
- `0.5s` 停顿不会完成语句，超过 hangover 的停顿会完成语句。
- 只有确认语音重置 10 秒计时，环境噪音不能延长会话。
- flush、静默超时和服务异常都只发送一次最终状态并释放会话。

### 10.3 真实模型与浏览器验证

- 使用已安装的完整 Fun-ASR-Nano-2512 和 CUDA 服务测试中文连续句子、短暂停顿、真实静音及背景白噪音。
- 使用虚拟麦克风把固定测试音频送入真实 WebSocket 服务，验证 partial/final 顺序和 10 秒停止。
- 在 GPT、智能画布 Prompt 和 OpenShop 文本框验证连续听写、光标、入口位置和页面切换。
- 以桌面尺寸和缩放后的视口截图检查白天、黑夜按钮、彩虹识别环和状态提示对比度。
- 回归现有语音单元测试、真实模型测试及相关 HstarA 页面测试。

## 11. 验收标准

1. 聚焦合格文本框时显示入口；失焦、切换功能页面或目标不可见时不残留。
2. 入口在滚动、缩放、节点移动和 iframe 变化后仍绑定目标右上角。
3. 白天模式为黑底白色麦克风，黑夜模式为近白底黑色麦克风；状态文字在两种模式下均清晰可见。
4. 有效语音识别期间显示不改变布局的彩虹波动圆环，减少动态效果模式下使用静态环。
5. 点击入口不会丢失文本焦点和选区，连续识别结果不会倒插或乱序。
6. 模型已安装时麦克风权限请求不等待模型冷加载；模型缺失时不请求权限。
7. `0.5s` 左右的停顿不会立即结束句子，连续 10 秒无有效语音仍会自动提交并释放设备。
8. 白噪音和短促低能量声音不产生文字，不依赖固定幻觉词黑名单。
9. GPT、智能画布 Prompt、OpenShop 和嵌套 iframe 的真实模型流程通过。
10. 模型、运行时、本地缓存和录音数据仍不进入仓库或安装包，5000 端口稳定软件不受影响。
