# OpenShop 图像导入、吸管与性能优化设计

## 背景

本轮解决三个相互关联的问题：

1. “文件 > 打开图像”当前会调用 `createNewDocument()`，导致现有画板、图层和历史被替换。用户需要的是在已经建立的文档中导入新的素材图层。
2. 吸管工具优先调用浏览器系统级 `EyeDropper`，回退分支又尝试调用 Fabric Canvas 不存在的 `getContext()`，无法稳定采样 OpenShop 画布。
3. 多个工具操作完成后会同步执行整画布序列化、图层和历史面板重建、导航器图片导出及直方图像素扫描。4K 文档中这些派生更新会阻塞主线程，使工具启动和操作反馈迟缓。

## 目标

- 本地图像和 GIF 导入后成为当前文档中的独立素材图层。
- 保持当前画板尺寸、视口、已有图层、历史和导出尺寸不变。
- 吸管准确读取 OpenShop 当前可见合成画面的颜色。
- 系统性减少重复渲染、重复 DOM 重建和不可见辅助面板的同步计算。
- 保持撤销历史、导出质量、图层语义和后台生成任务的可靠性。

## 非目标

- 不改变“新建文档”的行为。
- 不改变“打开 PSD”和“打开工程”作为完整文档载入的语义。
- 不重写 Fabric.js 或拆分整个单文件编辑器架构。
- 不通过降低文档分辨率、图片质量或历史完整性换取速度。

## 图像导入设计

### 普通图片

“文件 > 打开图像”支持现有允许的 PNG、JPEG、WebP、BMP 等格式。文件完成校验和解码后：

1. 创建一个新的普通素材图层，名称取安全化后的文件名。
2. 将解码后的 Fabric 图片对象放入该图层，并将该图层设为活动图层和唯一选中图层。
3. 图片使用原始像素尺寸，默认以画板左上角为原点放置，不自动按画板缩小，不裁切，也不改变文档尺寸。
4. 图片大于画板时允许超出画板边界；图片小于画板时不自动拉伸。
5. 一次成功导入只产生一条历史记录，并更新必要的图层和画布状态。

拖放和剪贴板粘贴保留各自现有的放置语义，不在本轮强制改成左上角原尺寸导入。

### GIF

GIF 同样保持当前文档：

- 多帧 GIF 创建一个独立动画素材图层，并保留帧数据、当前帧索引和时间轴能力。
- 首帧作为该图层在画布上的可见对象，使用原始尺寸并放置在画板左上角。
- 多帧解码失败时尝试以静态图片图层导入；静态解码也失败时不修改当前文档。
- 导入 GIF 不调用 `createNewDocument()`，也不重置已有动画之外的文档状态。

### 事务边界

只有完成文件校验和图片解码后才创建图层。任何校验、读取或解码错误都必须保证画板、图层、活动选择和历史数量不变。文件名只用于图层显示，不覆盖当前文档名称。

## 吸管设计

吸管不再依赖系统级 `window.EyeDropper`。用户在画布内单击时：

1. 使用事件的屏幕坐标定位 Fabric 上层合成画布中的实际设备像素。
2. 根据合成画布的 CSS 尺寸与像素缓冲区尺寸换算 Retina 比例。
3. 从 Fabric 已经渲染的合成画布读取一个像素，因此结果自然包含图层可见性、透明度、混合模式和对象叠加效果。
4. 将 RGB 转换成六位十六进制颜色，更新前景色并显示中文结果提示。

视口缩放和平移已体现在合成画布内容中，因此采样以屏幕点击位置为准，不再二次套用 `viewportTransform`。点击合成画布外部、读取越界或安全策略导致读取失败时，保持原前景色不变并显示明确中文提示。

透明像素按用户当前屏幕上看到的最终合成颜色采样；不单独返回 Alpha，也不改变背景色。

## 性能架构

### 更新调度器

增加编辑器内部的轻量更新调度器，以脏标记管理以下派生更新：

- 主画布视觉刷新
- 图层面板
- 历史面板
- 状态栏和无障碍树
- 导航器
- 直方图

同一帧内的重复请求合并为一次。主画布交互反馈使用 `requestAnimationFrame`；导航器和直方图等非关键派生内容优先使用空闲调度，并提供定时回退，避免长期不刷新。

### 历史提交

历史快照仍在一次编辑操作完成时同步生成并立即入栈，确保用户完成操作后可以立刻撤销。`saveHistory()` 只负责历史数据、脏状态和事件通知；历史面板、状态、导航器及直方图通过调度器分别刷新。

本轮不异步化 Fabric `toJSON()`，避免连续操作之间出现历史顺序或对象引用错误。基准测试若证明序列化仍是主要瓶颈，将结果记录为后续独立优化项，不在本轮冒险改变历史模型。

### 导航器与直方图

- 仅在对应面板可见时实际计算；隐藏期间只保留脏标记。
- 用户切换到对应面板时立即消费脏标记并刷新。
- 导航器生成预览时不得临时修改主画布 `viewportTransform`，也不得为了生成一张缩略图让主画布连续重绘两次。
- 直方图从稳定的合成源读取缩小后的样本，限制采样尺寸，并避免对 4K 全图进行无必要同步遍历。

### 工具与高频交互

- 工具切换缓存工具按钮、选项组和常用覆盖层引用，避免反复执行全局 DOM 查询。
- 只切换上一工具和当前工具的视觉状态，避免重写所有工具按钮状态。
- 画笔按类型复用；仅在画笔类型或参数变化时重新配置。
- 对象交互属性只在工具模式确实发生变化时更新，并始终重新应用锁定图层约束。
- 鼠标移动、缩放、平移、触摸缩放和临时图形拖动中的重复渲染每帧最多执行一次。
- 纯缩放、颜色或光标变化不重建图层列表和无障碍图层树。

## 错误处理

- 图片无效、尺寸超限或解码失败：显示中文错误，当前文档不变。
- GIF 多帧失败：降级静态图片；完全失败时不产生空图层或残留时间轴状态。
- 吸管越界或读取失败：不改变前景色，并显示中文提示。
- 调度回调中的单个辅助面板失败：记录调试信息，不阻断画布编辑和后续调度。
- 关闭 OpenShop 页面只影响界面可见性，不中断由 HstarA 宿主持有的后台生成任务。

## 测试策略

### 单元测试

- 普通图片导入新增独立图层，不调用 `createNewDocument()`。
- 导入保持 `canvasW`、`canvasH`、已有图层、文档名和既有历史。
- 导入对象保持原始尺寸并位于 `(0, 0)`。
- GIF 成功和静态降级路径都不重建文档。
- 解码失败时不留下部分图层。
- 吸管在 1 倍、缩放、平移和 Retina 场景下采到正确 RGB。
- 吸管覆盖混合后的颜色、透明区域、越界和读取异常。
- 同一帧内重复刷新被合并；隐藏的导航器和直方图不执行昂贵计算。
- `saveHistory()` 立即增加历史项，但辅助面板通过调度器更新。

### 浏览器集成测试

- 在已有多图层画板中导入真实 PNG，验证新增图层、原文档尺寸和已有对象不变。
- 导入真实 GIF，验证当前文档不被替换且时间轴可用。
- 在可见图层叠加、缩放和平移后使用吸管，验证前景色与屏幕像素一致。
- 对 4K 单图层和 4K 多图层文档测试工具切换、缩放、平移和一次历史提交。

### 性能基准

记录三档场景：800x600 小画布、4K 单图层、4K 多图层。至少测量：

- 工具切换同步耗时
- 一次普通对象修改后的历史提交耗时
- 导航器和直方图调用次数
- 连续缩放或平移期间的主画布渲染次数

验收以优化前后同机对比和调用次数为主，避免使用对 CI 环境过度敏感的绝对毫秒硬门槛。

## 数据隔离

自动化浏览器测试只允许使用 `3010` 工程测试实例及其隔离数据根。测试结束后删除测试画布和临时素材，不得写入或清理 `3000` 工程实例、`E:\Hstar缓存` 或任何稳定安装版数据。

## 验收标准

1. “打开图像”导入所有受支持图片和 GIF 时，当前画板尺寸、已有图层和历史不被重置。
2. 每个成功导入文件产生一个独立素材图层，普通图片保持原始尺寸并默认位于画板左上角。
3. “打开 PSD”“打开工程”和“新建文档”继续保留原有完整文档语义。
4. 吸管在缩放、平移和 Retina 显示下都能准确读取当前可见合成颜色。
5. 吸管失败不会改变前景色或阻断后续编辑。
6. 导航器和直方图不再在每次历史提交时同步阻塞主线程，也不会在隐藏时重复计算。
7. 高频交互的重复渲染被按帧合并，工具切换不再进行无必要的全量 DOM 更新。
8. 撤销、重做、图层锁定、导出原始尺寸、汉化和后台生成任务保持正常。
9. 单元测试、汉化审计和相关 Playwright 回归全部通过，隔离测试数据在结束后清理。
