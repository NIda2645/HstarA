# OpenShop 字体、OCR 与项目保存修复设计

## 目标

修复 OpenShop 的字体目录、OCR 文本图层排版、全局错误提示和项目持久化问题，同时保留现有 `01免 / 02免 / 03免` 免费商用字体池与已有画布数据。

## 字体目录

- 英文匹配失败时统一回退到已安装字体 `03免 阿里妈妈灵动体VF`。
- 使用 `fontTools` 读取 Windows 已安装字体文件中的真实 family、subfamily、字重、斜体和可变字体轴元数据，不再仅靠注册表显示名或名称后缀猜测字型。
- GDI 枚举继续用于补充 Windows 可用字体；字体文件元数据是字型分类的权威来源。无法读取的字体才使用现有保守推断。
- 字体家族仅列出真实可用的字型。只有 Regular 的字体只显示 Regular；可变字体根据真实轴能力生成适用字重，不伪造斜体。
- 文本属性面板标题统一为“字型”。
- 字体候选列表的显示名称使用实际可加载的字体 face 渲染；标题和分组继续使用界面字体，避免影响可读性。

## OCR 文本图层

- OCR 创建的横排和直排文本对象及字符级样式都将 `charSpacing` 固定为 `0`。
- 排版拟合不再通过增大字距填满识别框，也不把字号放大到模型识别值以上。
- 当真实字体字面超过 OCR 区域时，只允许等比缩小字号；对象保持 `scaleX = scaleY = 1`，避免压缩字形。
- 使用 OCR 四点框左上角、角度和可见字形边界定位。字号拟合优先匹配文字的横向/纵向厚度，流向长度仅用于判断是否需要缩小。
- 保留每个文字块独立的字号、字重、斜体、颜色、行距、对齐、角度、描边和阴影，不进行全局统一。

## 错误提示

- `OCR model did not return reliable text positions` 等 OCR 定位质量错误转换为简体中文。
- OCR 识别失败或结果缺少可靠位置时，提示显示在文字提取窗口内，不污染 OpenShop 顶栏的全局项目状态。
- 顶栏红色错误仅用于项目加载、保存和宿主通信等会阻断当前项目的错误；已恢复或重新执行成功后清除旧错误。
- 对同一路径上的上游英文错误做统一映射，未知错误使用简体中文前缀并保留必要技术详情。

## 项目持久化

- 编辑器为每次脏变更维护单调递增的修订号，并将自动保存请求合并，保证最新修订最终被服务端确认。
- 关闭 OpenShop 时先请求最新项目快照，等待项目 `PUT` 成功后再隐藏窗口；保存失败则保留窗口并显示简体中文错误。
- 页面刷新或退出时触发最后一次保存请求；已有待保存请求完成后再确认当前修订是否已落盘。
- 项目继续使用稳定的 `canvasType / canvasId / nodeId / projectId` 所有权绑定，不新建替代项目，不迁移或删除已有项目文件。

## 失败处理

- 字体文件解析失败时降级到 GDI/注册表元数据，并记录单个字体的诊断信息，不让整个字体目录不可用。
- 字体预览 face 不可加载时仅回退界面字体，不影响选择和项目加载。
- OCR 缺少可靠四点框时不创建位置不可信的文本图层，并在文字提取窗口给出可重新执行的中文提示。
- 保存冲突沿用版本检查；宿主重新拉取当前项目后提示用户重试，不静默覆盖较新版本。

## 验证

- Python 单元测试覆盖真实字体元数据、可变字体、单 Regular 字体和精确英文回退。
- Vitest 覆盖字体实际样式预览、“字型”标题、OCR 零字距、禁止放大和溢出缩小。
- 宿主测试覆盖编辑、关闭、重新打开以及刷新后的同项目恢复，并验证关闭必须等待保存确认。
- OCR 错误测试验证英文定位错误被中文化且不会显示在全局顶栏。
- 构建集成资源后校验源文件与 `static/openshop` 输出一致，再重启 HstarA 做真实浏览器验证。
