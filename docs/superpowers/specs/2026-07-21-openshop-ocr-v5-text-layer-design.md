# OpenShop OCR v5 文本图层重建设计

## 目标

重建 OpenShop 的文字识别和文本图层创建链路，使每个识别文字块在创建为可编辑文本图层后，保留原图中的位置、可见大小、字重、字型、方向、角度、颜色、字距、行距、对齐、描边和阴影。

本设计以稳定、单一、可验证的布局规则取代现有 OCR Schema v4 中相互叠加的逐字框、像素吸附、标点权重和旧布局修复逻辑。

## 已确认规则

- 执行文字提取时识别图像中所有可见文字。
- 文本行是定位单位，段落是图层合并单位。
- 同一段落中字体、字号、字重、方向、角度和行距连续一致的多行文字合并为一个可编辑文本图层。
- 不同文本行之间的属性明显变化时拆分为独立文本图层；同一行内的中英文属性变化使用字符区段样式，不拆图层。
- 中英文混排保留在一个文本图层中，使用字符区段样式应用不同字体和字型。
- 简体中文优先从 `01免` 字体池匹配。
- 繁体中文优先从 `02免` 字体池匹配。
- 英文优先从 `03免` 字体池匹配。
- 中文无可靠匹配时回退到本机已安装的“阿里巴巴普惠体 3.0”。
- 英文无可靠匹配时回退到本机已安装的“阿里妈妈灵动体”。
- 匹配字体后必须选择最接近识别字重的真实字型，不允许把所有文字统一为 Regular。
- 艺术字先创建可编辑本地字体载体，保留艺术字标记；用户修改文字后再主动执行艺术字处理。
- 文本对象始终保持 `scaleX=1` 和 `scaleY=1`，不通过拉伸或压缩伪造原字体轮廓。
- 由于替代字体的字形可能与原字体不同，应用层保证可见边界和基线定位，不承诺替代字形轮廓与原字形逐像素相同。

## 废弃的 OCR v4 逻辑

新识别任务和新建文本图层不再使用：

- `fontMetricQuad`
- `glyphQuads`
- 根据字体颜色在原图中寻找逐字像素的校准
- 将标点按 `0.2` 主轴权重折算的布局补偿
- 以主文字框和全文框反复重算字号和字距
- 针对历史直排文本对象的自动布局修复
- 任何非等比对象缩放

这些字段可继续作为旧项目数据读取，但不参与 OCR v5 图层创建。

## OCR Schema v5

服务端继续返回顶层 `blocks` 列表，每个 block 只表示一个可见文本行，行内样式差异由 runs 表示。

```json
{
  "schemaVersion": 5,
  "width": 1920,
  "height": 1080,
  "blocks": [
    {
      "id": "ocr-1",
      "text": "清凉自来",
      "quad": [
        {"x": 0.12, "y": 0.10},
        {"x": 0.18, "y": 0.10},
        {"x": 0.18, "y": 0.55},
        {"x": 0.12, "y": 0.55}
      ],
      "writingMode": "vertical",
      "rotation": 0,
      "align": "left",
      "paragraphId": "paragraph-1",
      "lineIndex": 0,
      "confidence": 0.98,
      "runs": [
        {
          "start": 0,
          "end": 4,
          "script": "zh-hans",
          "familyCandidates": ["Candidate Family"],
          "size": 96,
          "weight": 600,
          "style": "normal",
          "artistic": false,
          "styleDescription": "upright medium-weight sans",
          "color": "#356D4B",
          "letterSpacing": 0,
          "lineHeight": 1.1,
          "strokeColor": "#00000000",
          "strokeWidth": 0,
          "shadow": {
            "color": "#00000000",
            "blur": 0,
            "offsetX": 0,
            "offsetY": 0
          }
        }
      ]
    }
  ]
}
```

### 坐标规则

- `width` 和 `height` 必须等于文字识别时上传的整张画板图像尺寸。
- `quad` 是文本行全部可见字形的紧边界，包含标点，四点按局部左上、右上、右下、左下顺时针排列。
- 坐标归一化到 `0..1`，只相对于上传的整张画板图像。
- `writingMode` 只描述文字流向，`rotation` 只描述整个文本行角度，两者不互相推导。
- OCR 返回尺寸与上传源图不一致时，整次创建失败，不默默使用画板尺寸重新估算。

### 样式区段规则

- `start` 和 `end` 使用 Unicode 码点索引，区间为左闭右开。
- runs 必须完整、不重叠地覆盖 block 文本中所有非换行字符。
- 每个 run 独立识别字体、字号、字重、字型、颜色、字距、描边和阴影。
- 单个无效 run 使整个 block 进入低可信状态，不用相邻 run 的属性填充。

## 识别流程

1. OpenShop 导出当前选中像素图层，保留它在整个画板中的位置、缩放和角度，输出尺寸与画板完全一致。
2. 视觉模型只生成 Schema v5 文本、单一四点框和样式区段，不生成逐字定位或第二套几何框。
3. 服务端对每个 block 独立验证，返回有效 block 和明确 warnings，不使用像素颜色再次移动几何。
4. 文字提取窗口保存 Schema v5 结果和用户校对文本。
5. 用户点击“创建文字图层”后，客户端先加载本机字体目录并完成所有 run 的字体预检。
6. 所有字体和字型确定后，创建离屏文本对象并求解最终字号、字距、行距和位置。
7. 全部文本块成功求解后才原子性加入画板和图层面板。

## 本机字体匹配

### 字体池

- `zh-hans` -> `01免`
- `zh-hant` -> `02免`
- `en` -> `03免`
- `mixed` -> 按 run 拆分后分别使用对应字体池

只有存在本机字体文件并能被 Canvas 真实渲染的字体才能参与匹配。

### 字体匹配

字体家族匹配使用下列顺序：

1. OCR 候选名称与本机字体本地名称的精确匹配。
2. 去除 `01免 / 02免 / 03免`、字型后缀、安装器编号和标点差异后的规范化名称匹配。
3. 候选名称相似度与 `styleDescription` 中的衬线、笔画对比、宽度、圆角和装饰特征评分。
4. 评分低于可靠阈值时禁止选择看似相近但实际无关的字体，直接使用回退字体。

回退规则：

- `zh-hans` 和 `zh-hant` -> `阿里巴巴普惠体 3.0`
- `en` -> `阿里妈妈灵动体`

必需回退字体未安装时，创建整体失败并显示缺失字体名称，不改用其他商业字体。

### 字型匹配

在已选字体家族中，根据 OCR run 的数值字重和斜体状态选择真实字型：

- 优先保持斜体状态。
- 其次选择与目标字重数值距离最小的字型。
- 同距离时优先不超过目标字重的字型，避免无故加粗。
- 实际对象使用该字型的真实 face family，同时保存家族名、字型 ID、数值字重和斜体状态。

## 文本布局求解

### 单行文字

1. 使用已匹配的真实字体、字型和字符区段样式创建文本对象。
2. 清除对象缩放，设置 `scaleX=1` 和 `scaleY=1`。
3. 在离屏 Canvas 中渲染并扫描 alpha 像素，获得文字对象的真实可见边界。
4. 横排以 `quad` 的可见高度求解字号，直排以 `quad` 的可见宽度求解字号。
5. 在字号固定后，以主轴长度求解字距；字距只作用于字符间隙，不改变字形比例。
6. 按文本对象可见边界相对对象原点的偏移，经过 `quad` 角度的旋转矩阵计算最终 `left` 和 `top`。
7. 可见边界落位后不再执行任何自动补偿或历史修复。

单字或单个标点没有可调整的字符间隙。当替代字体轮廓长宽比与原字形不同时，以交叉轴尺寸和可见左上落点为硬约束，不拉伸字形。

### 多行段落

- 客户端按 `paragraphId`、`writingMode`、`rotation` 和样式连续性分组。
- 段落内每行保留自己的 `quad`，第一行确定段落落点，相邻行 `quad` 间距确定真实行距。
- 只有字号和样式连续的行才合并。无法用一个统一行距重现所有行位置时不合并，而是保留独立图层。
- 段落内的混排 runs 转换为 Fabric 字符级 styles，属性面板在选中文字时读取当前字符区段属性。

## 低可信度与错误处理

- OCR 结果中文本可识别但样式置信度低时，仍保留 block 并在校对界面显示低可信标记。
- 用户校对修改文本内容时不覆盖原始 `quad` 和视觉属性。单 run 文本的 run 自动扩展到新文本全长；多 run 文本使用 Unicode 差异映射保留未改变字符的样式，新插入字符按它的语种和相邻 run 继承样式。
- 任一必需回退字体缺失、字体加载失败、图像尺寸不一致、几何无效或可见文字无法测量时，整次创建中止。
- 失败时不向画板、图层列表或操作历史写入半成品。
- 不自动重试文字识别，瞬时断线后等待用户再次主动执行。

## 历史数据处理

- OCR Schema v4 及更早结果继续保存在项目中并可在文字提取窗口查看。
- 旧结果的“创建文字图层”按钮禁用，显示“旧版识别结果，请重新执行文字提取”。
- 已存在于画板中的旧文本图层保持原样，不自动移动、修复、删除或改变字体。
- 新建 OCR v5 文本图层不执行任何 v4 布局修复。
- 同一份 v5 识别结果可重复点击“创建文字图层”，每次创建一套新的独立图层。

## 艺术字载体

- OCR run 的 `artistic=true` 只表示原图文字有艺术风格，不把文本图层栅格化。
- 艺术字 run 仍按语言类别使用 `01免 / 02免 / 03免` 字体池匹配，匹配失败时使用对应中英文回退字体。
- 文本对象保存原始源图资产、`quad`、原始文本、视觉属性和艺术字标记。
- 用户可修改载体文字，艺术字处理使用当前文字，原文本只作为样式来源。

## 验证策略

### Python

- OCR prompt 只请求 Schema v5 的 `quad` 和 runs，不请求 `fontMetricQuad` 或 `glyphQuads`。
- 规范化器验证线级四点框、Unicode run 覆盖、样式数值范围和顶层尺寸。
- 无效 block 产生明确 warning，有效 block 不受影响。
- 字形像素吸附函数不再被 OCR 任务调用。

### OpenShop 单元测试

- 简体、繁体、英文和混排 runs 使用正确字体池。
- 中文和英文分别使用“阿里巴巴普惠体 3.0”和“阿里妈妈灵动体”回退。
- 字型选择覆盖 Thin、Light、Regular、Medium、SemiBold、Bold、ExtraBold 和 Black。
- 横排、直排和旋转文字的可见边界落在目标 `quad` 内，左上落点误差不超过 1 个画板像素。
- 文本对象最终 `scaleX=1` 和 `scaleY=1`。
- 字号先由交叉轴可见尺寸求解，字距只调整主轴长度。
- 标点是普通文本内容，不触发特殊尺寸或位置补偿。
- 多行段落只在全部行位置可由统一行距表示时合并。
- OCR v4 结果不能新建文本图层，v5 结果可重复创建。
- 字体加载或任意 block 布局失败时不产生部分图层。

### 集成与真实验证

- 使用确定性横排、直排、旋转、标点、混排和多行图像夹具生成文本图层并测量像素边界。
- 对每个创建图层记录目标 `quad`、实际可见边界、字体 family、face、字重、字号、字距、行距和对齐误差。
- 使用当前授权的视觉 API 对既有原图执行至少一次真实 OCR，然后创建图层并生成对比截图。
- 真实 API 结果必须满足 Schema v5 验证；验证失败时显示错误，不使用 v4 补偿路径。

## 验收标准

- 每个新建文本行的实际可见左上落点与 OCR `quad` 左上落点的画板误差不超过 1 像素。
- 可见交叉轴尺寸与 `quad` 差异不超过 1 像素；主轴通过真实字距尽可能匹配，不拉伸字形。
- 所有对象保持 `scaleX=1`、`scaleY=1` 且数值有限。
- 不同 block 不共享默认字号、字重、字距、行距、颜色或效果。
- 识别为非 Regular 的文字在目标 family 存在对应字型时不得创建为 Regular。
- 混排文本在一个可编辑图层中保留中英文字体区段。
- 文本提取结果在关闭 OpenShop 和重新打开后仍然可查看，v5 结果仍可重复创建图层。

## 非目标

- 本轮不接入 PaddleOCR 或下载本地 OCR 数据包。
- 不通过非等比缩放模仿未安装的原字体轮廓。
- 不修改已经存在于画板中的旧 OCR 文本图层。
- 不改变已确认的艺术字局部重绘任务语义。
