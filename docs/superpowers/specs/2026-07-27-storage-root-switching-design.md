# Hstar 存储根目录直接切换设计

## 目标

软件设置中的“自定义储存”只负责切换活动数据根目录，不负责迁移数据。用户从 Y 切换到 X 后，Y 保持原样；Hstar 重启后读取 X，并将新产生的数据写入 X。用户以后切回 Y 时，继续读取和使用 Y 中原有数据。

## 行为契约

- 用户选择的 X 本身就是 Hstar 数据根目录，不自动增加 `Hstar缓存` 子目录。
- X 不存在时自动创建。
- X 无论为空、包含已有 Hstar 数据，还是包含普通文件，都允许切换。
- 切换过程不扫描、不哈希、不复制、不删除、不清理 Y。
- 切换过程不移动、不删除 X 中的普通文件。
- Hstar 只创建或更新自身约定的数据路径，例如 `config`、`canvases`、`assets`、`outputs` 和兼容旧协议所需的既有路径。
- 如果 X 中存在与 Hstar 保留路径同名但类型或结构不兼容的内容，切换仍然成功；实际访问该功能时返回明确的路径冲突错误，不覆盖冲突内容。
- X 采用旧版 Hstar 缓存布局时继续按旧协议兼容读取；空目录或新目录产生的数据使用新版布局。
- 切换完成后必须受控重启。运行中不热切换全局路径，避免不同模块分别写入 Y 和 X。

## 架构

保留现有后台任务、存储写入屏障和桌面壳受控重启链路，但将软件设置入口创建的任务统一定义为 `switch_storage`。该任务只执行以下步骤：

1. 解析并验证 X 是程序目录之外的可访问目录。
2. X 不存在时创建目录，并验证目录可写。
3. 将当前进程置于只读切换阶段，等待已获准的写任务结束。
4. 原子更新独立于数据目录的 bootstrap 配置，将 `data_root` 指向 X，并记录 Y 为 `previous_data_root`。
5. 返回完成状态，由桌面壳使用 X 受控重启 Hstar。

现有通用迁移实现可以保留给独立维护工具或未来安装器使用，但软件设置不得再调用复制迁移入口。

## 界面

- 保存后显示“正在应用存储位置”。
- 完成后显示“存储位置已切换，正在重新启动 Hstar”。
- 不显示迁移字节数、复制文件名或“迁移完成”等文案。
- 浏览器开发模式无法自动重启时，提示用户重新启动 Hstar 以读取所选位置。
- 切换任务通常很短；底层取消能力保留用于异常阻塞，但界面不再把操作表达为数据迁移。

## 安全与错误处理

- 不允许 X 等于 Y、位于 Y 内部、包含 Y，或位于 Hstar 程序目录内。
- 写权限检查只创建并删除专用临时探针，不改写已有业务文件。
- bootstrap 更新失败时保持 Y 为活动根目录，并解除只读屏障。
- bootstrap 更新成功后，旧进程保持只读并等待重启，禁止继续产生写入。
- 任意普通文件和未知目录均不因切换而删除、重命名或覆盖。

## 测试

- 从含数据的 Y 切换到空 X，断言 Y 未变化且没有文件复制到 X。
- 从 Y 切换到含普通文件的 X，断言切换成功且普通文件字节、大小和修改时间未变化。
- 从 X 切回 Y，断言 bootstrap 恢复指向 Y。
- X 不存在时自动创建并完成切换。
- 程序目录、重叠目录和不可写目录保持拒绝。
- 前端断言不再出现迁移字节进度和迁移文案，并正确触发受控重启。
- 全量源代码门禁、编码审计、敏感信息审计和静态缓存一致性检查全部通过。
