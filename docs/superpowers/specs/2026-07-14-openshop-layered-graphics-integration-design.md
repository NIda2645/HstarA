# HstarA OpenShop 图文分层融合设计

日期：2026-07-14

状态：总体设计已确认；阶段 1 技术验证和阶段 2 汉化本地化已完成，阶段 3 进入实施

## 1. 目标

将 `SysAdminDoc/Openshop` 作为 HstarA 内置的轻量分层图像编辑器，并在普通无限画布和智能画布中同步增加“图文分层”节点。

最终能力包括：

- 对 OpenShop 全部用户可见界面进行简体中文汉化，既有 Photoshop 概念采用中文版 Adobe Photoshop 的通用术语。
- 点击“图文分层”节点后，在 HstarA 内部进入全屏 OpenShop 编辑工作区，并能准确返回来源画布。
- 将多个上游图片节点按稳定的接入顺序转换为独立图层。
- 让同一画布中的多个“图文分层”节点、不同画布中的节点以及两类画布中的节点完全隔离。
- 复用并实时同步 HstarA 全局 API 配置，在每项 AI 功能中提供明确的 API 和模型选择按钮。
- 支持文字提取、去除文字、生成式填充、局部重绘和 AI 生成图层。
- 支持中英文及 Unicode 文字、字体匹配、字体导入和缺失字体提示。
- 支持非破坏式图层、蒙版、橡皮擦、混合和局部透明结果图层。
- 将合成结果发送回画布，并导出 PNG、JPEG、WebP、HstarA 原生分层项目和 PSD。
- 在 4K 多图层场景下控制内存、缓存和主线程阻塞，并提供可靠的自动保存和故障恢复。

该功能定位为“轻量 Photoshop 工作流”，目标是可靠覆盖常用分层图像编辑，而不是宣称与 Photoshop 的全部高级对象、滤镜、CMYK 和 PSD 特性完全等价。

## 2. 上游基线与许可证

首个融合基线固定为：

```text
repository: SysAdminDoc/Openshop
commit: 60c93382868849b1f4f9b073f9519ae61136a05b
version: 0.19.1
license: MIT
```

OpenShop 的 MIT 许可证和 Matthew Parker 的版权声明必须随源码、构建产物和安装包保留。HstarA 仓库应记录上游提交、HstarA 补丁和后续升级历史，不能直接覆盖本地汉化和宿主桥改动。

已确认的上游特征：

- 当前应用主要集中在单个 `index.html` 和全局 `OS` 对象中。
- 核心依赖包括 Fabric.js 5.3.1、ag-psd 22.0.2、jsPDF、Transformers.js 和 Photon WASM。
- 用户界面没有正式的国际化层，存在大量硬编码英文字符串。
- 自动保存使用 OpenShop 自己的 OPFS 路径，最近文件、调色板和预设还会使用 localStorage。
- 当前 `exportPSD()` 会把每个 OpenShop 图层绘制成位图后交给 `ag-psd.writePsd()`，不能保留可编辑文字对象。
- Fabric.js 5.3.1 的升级和安全问题需要单独处理，但首期融合不同时进行 Fabric.js 大版本迁移，以避免扩大回归范围。

## 3. 范围边界

### 3.1 本计划包含

- OpenShop 源码托管、依赖本地化、完整简体中文汉化和术语表。
- HstarA 全屏编辑器宿主、消息桥和同源静态资源加载。
- 普通画布与智能画布的“图文分层”节点适配器。
- 每节点独立项目、素材、字体引用、AI 任务和自动保存。
- 多图片转图层、来源绑定、更新提示、断线和删除生命周期。
- HstarA 全局 API 配置、模型发现、能力判断和任务日志的复用。
- 文字提取、去除文字、生成式填充、局部重绘和 AI 生成图层。
- 中英文与 Unicode 文字、系统字体、内置开源字体和用户字体库。
- 图片导出、HstarA 原生分层项目和增强 PSD 导出。
- 4K 性能、内存释放、异常恢复、安全和安装包验证。

### 3.2 本计划不包含

- 在每个画布节点卡片中常驻完整 Fabric.js 编辑器。
- 在 OpenShop 内维护另一套 API 地址和密钥。
- 首期迁移 Fabric.js 7.x 或重写全部 OpenShop 编辑器核心。
- 对 Photoshop 全部智能对象、调整图层、专有滤镜、CMYK、16/32 位通道和复杂 PSD 效果作无条件兼容承诺。
- 在未验证字体许可证时将商业字体复制、嵌入项目包或随安装包分发。
- 将普通 LLM 的纯文本回答误当成带位置和样式的 OCR 结果。

## 4. 方案选择

采用“托管 OpenShop 分叉 + HstarA 服务桥”方案。

OpenShop 保留 Fabric.js 编辑器和现有图层工具，HstarA 负责节点生命周期、项目存储、素材管理、API 配置、AI 请求、任务日志、文件导出和画布回传。两者通过同源、版本化、可校验的 Host Bridge 通信。

未采用的方案：

1. 最小 iframe 包装：开发快，但不能可靠解决多节点隔离、API 同步、任务收尾和大型素材传输。
2. 完全重写为 HstarA 原生编辑器：长期边界清晰，但会重复实现大量成熟图像编辑细节，首期成本和风险过高。

建议的仓库布局为：

```text
integrations/openshop/             OpenShop 上游源码、许可证、补丁和测试
static/openshop/                   固定版本的本地构建产物
static/js/openshop-protocol.js     消息协议和运行时校验
static/js/openshop-host.js         全屏宿主、会话和导航
static/js/canvas-openshop.js       普通画布适配器
static/js/smart-canvas-openshop.js 智能画布适配器
API/                               项目、素材、字体、AI 与导出服务
```

最终路径在实施计划中对照 HstarA 现有模块进一步细化，但职责边界不得改变。

## 5. 系统架构与职责

### 5.1 画布适配器

普通画布和智能画布各有一个薄适配器，但共享同一节点协议和项目格式。适配器负责：

- 创建、复制、删除和加载“图文分层”节点。
- 读取上游图片边并生成稳定的来源绑定。
- 打开全屏编辑器并提供来源画布上下文。
- 更新节点预览和保存状态。
- 将编辑结果创建为普通图片节点并建立输出边。
- 通过现有画布持久化路径保存节点和连线。

### 5.2 项目协调器

项目协调器是每个 OpenShop 工程的生命周期所有者，负责：

- 为每个节点分配稳定、唯一的 `projectId`。
- 根据 `canvasType + canvasId + nodeId + projectId` 校验项目归属。
- 管理会话、自动保存、来源更新、任务和删除清理。
- 防止异步任务、自动保存或迟到消息串入其他节点。

### 5.3 OpenShop 编辑器

OpenShop 负责：

- Fabric.js 画布、图层树、选区、文字、变换、画笔、橡皮擦、蒙版、滤镜和混合交互。
- 显示简体中文界面和各 AI 功能按钮。
- 生成结构化项目变更、合成预览、选区蒙版和导出请求。
- 使用资源 ID，不持有 HstarA API 密钥或任意本地文件路径。

### 5.4 HstarA 宿主服务

HstarA 负责：

- 项目清单与二进制素材存储。
- 全局 API 配置、实时模型列表、能力注册和真实请求执行。
- 字体目录、字体元数据和许可证状态。
- 图片与 PSD 的读取、校验和导出辅助。
- 任务日志、取消、错误脱敏和恢复状态。

## 6. 节点设计与实例隔离

“图文分层”节点同时出现在普通画布和智能画布中，节点卡片包含：

- 项目名称和合成预览。
- 画布尺寸、图层数量和保存状态。
- 多图片输入端、合成图片输出端和“打开编辑器”按钮。
- 任务进行、失败和来源更新提示。

隔离单位必须是节点实例，而不是画布：

- 每个节点有独立 `projectId`，即使多个节点位于同一画布也不得共享项目状态。
- 图层、素材引用、字体引用、选区、蒙版、预设、撤销历史、AI 任务和导出记录均按 `projectId` 隔离。
- 自动保存键和临时资源不得只使用 `canvasId` 或 OpenShop 默认名称。
- 不同节点可以引用同一个原始素材，但每个节点保存自己的图层对象和编辑状态。
- 复制节点时克隆项目清单并生成新的 `projectId`；后续编辑互不影响。
- 删除节点时只删除该项目和无其他引用的素材，不影响同画布其他节点。
- 应用重启后，每个节点仍通过自己的 `projectId` 恢复。

每次打开全屏编辑器还会生成独立 `sessionId`。所有异步结果必须同时匹配 `projectId + sessionId + taskId`。项目被删除后，宿主拒绝迟到的保存和 AI 响应。

## 7. 图片输入与图层绑定

图片节点接入规则：

1. 第一张图片成为最底部的来源图层。
2. 后续接入图片依次放到上方。
3. 顺序依据画布持久化的连线序号，而不是网络下载或图片解码完成顺序。
4. 每个来源图层记录 `edgeId`、`sourceNodeId`、`assetVersion`、`layerId` 和接入序号。
5. 用户在 OpenShop 中手动重排后，现有图层顺序不再被连线刷新强制覆盖；新接入图片默认放到最上方。

上游图片重新生成或变更时：

- 图层显示“来源已更新”，但不自动覆盖已编辑内容。
- 用户可以选择替换原绑定图层、作为新图层加入或忽略当前版本。
- 已被编辑的来源图层默认推荐“作为新图层加入”。

断开连线时：

- 保留当前图层像素和编辑结果。
- 将来源绑定标记为已解除，不删除图层。

只有用户明确删除图层或删除整个“图文分层”节点时，才删除对应项目内容。

## 8. 全屏工作区与导航

点击节点后打开 HstarA 内部全屏 OpenShop 工作区。宿主在进入前保存：

- 来源页面和画布类型。
- 项目与画布 ID。
- 来源节点 ID 和项目 ID。
- 画布平移、缩放和当前选择。

顶部宿主工作区提供：

- “返回画布”
- “保存”
- “发送到画布”
- “导出”
- 项目名称和保存状态

关闭或返回时恢复来源画布和视口。点击“发送到画布”后，宿主合成当前可见图层，在当前节点下游创建新的普通图片节点、建立输出边并保存画布。重复发送会创建不同的输出版本，原分层项目继续保留和编辑。

保存项目时自动更新“图文分层”节点预览，但不自动写出系统文件。PSD、PNG、JPEG 和 WebP 只在用户明确执行导出时生成。

## 9. Host Bridge 协议

OpenShop 与 HstarA 使用同源、版本化消息协议。统一信封至少包含：

```text
type
protocolVersion
requestId
sessionId
context {
  canvasType
  canvasId
  nodeId
  projectId
}
payload
```

宿主发送给 OpenShop 的核心事件：

- `OPENSHOP_OPEN_SESSION`
- `OPENSHOP_LOAD_PROJECT`
- `OPENSHOP_ADD_IMAGE_LAYER`
- `OPENSHOP_SOURCE_UPDATE_AVAILABLE`
- `OPENSHOP_API_CATALOG_CHANGED`
- `OPENSHOP_TASK_UPDATE`
- `OPENSHOP_SAVE_CONFIRMED`
- `OPENSHOP_EXPORT_RESULT`

OpenShop 发送给宿主的核心事件：

- `OPENSHOP_READY`
- `OPENSHOP_CLOSE`
- `OPENSHOP_SAVE_PROJECT`
- `OPENSHOP_SEND_TO_CANVAS`
- `OPENSHOP_REQUEST_API_CATALOG`
- `OPENSHOP_REFRESH_MODELS`
- `OPENSHOP_REQUEST_AI_TASK`
- `OPENSHOP_CANCEL_AI_TASK`
- `OPENSHOP_EXPORT_IMAGE`
- `OPENSHOP_EXPORT_PSD`
- `OPENSHOP_REPORT_ERROR`

宿主只接受来自已注册同源 OpenShop 窗口的消息，并校验协议版本、会话、项目、画布、节点和请求去重状态。大型图片、PSD、字体和蒙版不通过 `postMessage` 传输 Base64，只传经过授权的资源 ID 或同源临时资源引用。

## 10. 简体中文汉化与术语

OpenShop 的硬编码用户界面文本必须抽取为正式国际化资源：

```text
locales/zh-CN.json
locales/en-US.json
locales/photoshop-terms.zh-CN.json
```

规则如下：

- 菜单、工具、面板、对话框、提示、错误、快捷键说明和无障碍标签全部进入语言资源。
- 既有 Photoshop 功能以当前中文版 Adobe Photoshop 的通用名称为准，例如“移动工具”“图层蒙版”“混合模式”“栅格化”和“生成式填充”。
- OpenShop 特有概念由术语表给出唯一中文名称，不允许同一功能出现多个译名。
- 内部命令使用稳定 ID，项目文件不保存依赖界面语言的业务枚举值。
- 简体中文为 HstarA 集成版默认语言，英文资源作为回退和维护对照。
- 自动检查未翻译字符串、重复术语、乱码字符和意外回退英文。

## 11. 多语言文字与字体

界面汉化不限制文档内容语言。文字模型和项目格式全程使用 Unicode，首期必须完整验收简体中文、英文和中英混排。

字体来源按以下顺序解析：

1. 用户系统已安装字体。
2. HstarA 安装包内许可明确的开源中英文及符号字体。
3. 用户导入到 HstarA 专用字体库的本地字体。
4. 项目记录的字体回退链。

字体记录至少包含字体家族、字重、字形、PostScript 名称、文件指纹、支持字符范围、来源和许可证状态。项目保存字体引用，不擅自复制或嵌入无分发许可的字体。

字体缺失时：

- 明确显示缺失字体和替代字体。
- 提供本机字体候选和用户导入入口。
- 不静默改变项目保存的字体名称。

普通图片导出按当前渲染结果栅格化，保证视觉稳定。PSD 导出在支持时保存可编辑文字和字体名称，目标电脑缺少字体时由导出检查提前提示。复杂文字系统和竖排功能只有通过排版与 PSD 往返测试后才能标记为支持，不以 Unicode 存储本身替代真实渲染验证。

## 12. HstarA 全局 API 同步

HstarA 全局 API 配置是唯一数据源。OpenShop 不创建第二套 API 地址、密钥或 CLI 配置。

同步规则：

- 复用 HstarA 现有配置读取、模型拉取、`studio-api` 广播和供应商适配器。
- 全局新增、修改、删除、启用或停用配置后，所有已打开 OpenShop 项目实时刷新可选列表。
- OpenShop 只保存 `apiConfigId + modelId + toolId` 引用和非敏感参数。
- 全局配置删除或模型不可用时显示“配置不可用”，禁止静默切换到其他模型。
- “刷新模型”调用 HstarA 的真实模型发现通道，显示实时返回结果，不写死模型数量或名称。
- HTTP API、推荐 API、Antigravity CLI 和后续供应商通过统一能力注册表暴露给 OpenShop。
- CLI 后台调用必须沿用 HstarA 无窗口执行方式；只有用户主动启动交互终端时才显示命令窗口。
- 实际请求、图片上传、取消、轮询、下载和错误日志全部由 HstarA 执行。
- 项目、图片、PSD 和日志不得包含 API 密钥。

OpenShop 的 API 选择窗口只负责选择、刷新和显示状态；“管理 API 配置”直接进入 HstarA 全局 API 设置，避免两套编辑界面产生冲突。

## 13. AI 功能按钮与能力路由

计划新增的每项功能都必须在 OpenShop 中提供明确按钮，不能只隐藏在菜单、快捷键或后台逻辑中。

左侧工具栏新增：

- “文字提取”
- “去除文字”
- “生成式填充”
- “局部重绘”
- “AI 生成图层”

OpenShop 原有选框、套索、移动、文字、画笔、橡皮擦和蒙版工具继续保留。

点击 AI 按钮后，在右侧打开对应参数面板。每个面板必须包含：

- “选择 API / 模型”按钮。
- 当前真实 API 服务名称和模型名称。
- “跟随全局默认”或“本项目单独指定”。
- 该功能需要的提示词、选区、尺寸、质量和其他参数。
- 执行、取消、重试和任务状态。

每个工具按 `projectId + toolId` 保存选择。模型列表只显示能力兼容项：

- 文字提取需要视觉识别和结构化布局输出能力。
- 去除文字需要原图输入和图像编辑能力。
- 生成式填充与局部重绘需要原图、选区或蒙版能力。
- AI 生成图层需要文生图能力，可选支持参考图。

按钮在条件不足时保持可见但禁用，并明确说明缺少图片、选区、有效 API 或兼容模型，不能点击后才无反馈失败。

## 14. 文字提取

“文字提取”是独立、非破坏式功能，只识别文字并创建可编辑文字图层，不修改、隐藏或替换原图片图层。

流程：

1. 用户选择一个或多个像素图层，或指定当前可见合成结果。
2. 用户通过功能面板选择 HstarA API 和视觉模型。
3. HstarA 发送原图并要求结构化 OCR/版面结果。
4. 结果归一化为文字、四点坐标、行段关系、语言、置信度、字号、颜色、字重、对齐、旋转和字体候选。
5. OpenShop 显示可视化校对，低置信度内容明确标记。
6. 用户确认后创建独立可编辑文字图层或文字图层组。

如果模型只能返回纯文本而不能提供可靠位置，界面必须说明能力不足，不得把全部文本堆叠到画布原点并声称提取成功。

## 15. 去除文字

“去除文字”与“文字提取”完全独立：

- 不要求先执行 OCR。
- 不自动创建文字图层。
- 不删除或改写原图片图层。
- 支持“整层自动去字”和“选区去字”。

HstarA 将源图、可选蒙版、功能提示词、模型和尺寸参数交给真实图像编辑通道。成功结果创建新的无字像素图层，原始图层保留。失败或取消时不创建残缺图层。

用户可以自行组合“文字提取”和“去除文字”，但系统不把两者捆绑成不可拆分流程。

## 16. 生成式填充、局部重绘与 AI 生成图层

### 16.1 生成式填充

使用选区周围上下文填充透明区域、删除区域或用户指定内容。输出为带蒙版的新局部图层。

### 16.2 局部重绘

替换选区内已有像素，同时保留选区外画面。请求包含当前合成图、精确蒙版、提示词、选区坐标、羽化和模型参数。

AI 返回结果后：

- 校验尺寸、格式、透明度和选区对应关系。
- 只保留选区及必要羽化边缘的局部像素。
- 按原坐标创建透明背景的新像素图层。
- 保留可编辑蒙版、提示词、模型、种子和源图版本。
- 允许重新生成、切换结果和使用橡皮擦进一步融合。

### 16.3 AI 生成图层

从提示词生成完整新图层，可选择是否使用当前可见合成图作为参考。生成结果作为独立图层加入当前项目，不覆盖现有图层。

## 17. AI 任务状态与错误处理

统一任务状态为：

```text
queued -> uploading -> generating -> downloading -> succeeded
                                              \-> failed
queued/uploading/generating/downloading       \-> cancelled
```

规则：

- 每个任务绑定 `projectId + sessionId + taskId + toolId`。
- 界面显示实际 API、模型、阶段和进度信息。
- 失败时立即结束进度状态，不留下永久“生成中”图层或占位节点。
- 用户取消后中止可中止的请求、停止轮询并清理临时素材。
- 关闭编辑器后任务可以在后台继续；再次进入项目时恢复状态。
- 删除节点时取消其未完成任务，并拒绝迟到响应。
- 任务日志记录阶段、配置 ID、模型 ID、状态码和脱敏后的上游错误，不记录密钥。
- 不支持原图或蒙版的模型不得进入对应请求通道。
- 供应商适配器必须通过真实图片上传测试后，才声明图生图或蒙版能力可用。

## 18. 项目数据与存储

项目清单至少包含：

```text
schemaVersion
projectId
owner { canvasType, canvasId, nodeId }
document { width, height, resolution, colorSpace, background }
layers
sourceBindings
fontRefs
aiToolPreferences
aiTaskRecords
assetRefs
previewAssetId
autosaveVersion
exportRecords
createdAt
updatedAt
```

存储原则：

- 项目数据库只存结构化清单和资源 ID。
- 原图、图层像素、蒙版、缩略图和 AI 结果存为独立二进制素材。
- 相同素材可以按内容哈希复用，但项目编辑状态保持独立。
- 禁止在画布 JSON、localStorage 或 Host Bridge 中长期保存大型 Base64。
- OpenShop 原有 OPFS 自动保存和通用 localStorage 键不能作为正式节点项目存储。
- 调色板和预设如需保留，必须明确区分“用户全局设置”和“项目专属设置”。

自动保存使用防抖、临时文件和原子替换。每次保存先写新版本并校验，再更新当前指针。保留有限恢复点和可序列化的近期撤销信息；大型像素素材通过引用和增量检查点复用，不能在每个撤销步骤中完整复制。

异常退出后，重新打开节点时提供最后一次已确认保存和较新的恢复快照。项目格式带版本号和迁移器，升级不能直接破坏旧项目。

## 19. 导出设计

### 19.1 发送到画布

合成当前可见图层，生成普通图片节点并自动连接到当前“图文分层”节点。该操作不删除项目，也不自动写入系统文件。

### 19.2 图片导出

支持 PNG、JPEG 和 WebP，提供透明背景、质量、尺寸和颜色配置。导出使用当前可见合成结果。

### 19.3 HstarA 原生分层项目

原生项目包保存项目清单和允许打包的素材，可用于备份和迁移。API 密钥、无授权字体和机器绝对路径不得进入项目包。

### 19.4 PSD 导入导出

不能直接沿用上游当前的全图层栅格化 `exportPSD()` 作为完成标准。需要增强 PSD 映射器：

- 保留图层树、名称、位置、可见性、不透明度、混合模式和支持的蒙版。
- 在 `ag-psd` 能可靠表达时写出可编辑文字、字体名称、字号、颜色、对齐和变换。
- OpenShop 特有效果或无法映射的对象栅格化为像素图层，但原生项目仍保留可编辑数据。
- 导出前显示兼容性报告，列出缺失字体、被栅格化对象和不支持的属性。
- 首期稳定目标为 sRGB、8 位文档。
- PSD 导入记录不支持项目，不静默丢失图层。

验收必须使用 Adobe Photoshop 打开黄金样例，检查中文、英文、混排、文字可编辑性、位置、透明度、混合模式、蒙版和重新保存后的往返结果。仅验证文件能下载或 OpenShop 能重新打开不算通过。

## 20. 性能、缓存与资源生命周期

- 图层面板优先加载缩略图，原始像素按需解码。
- 不可见图层延迟加载；大图滤镜、缩放、蒙版和合成优先进入 Worker、OffscreenCanvas 或 WASM。
- 自动保存、预览生成和 PSD 写出不得长期占用 HstarA 主线程。
- 及时释放 Object URL、临时 Canvas、纹理、图片解码对象和 AI 临时蒙版。
- 节点删除后清理项目专属缓存；共享素材只有引用计数归零后删除。
- 导出的用户文件不随节点删除。
- 连续打开和关闭不同节点后，内存不能持续单向增长。

性能基线使用 4096 x 4096、10 个普通像素图层的测试项目。该项目必须能够稳定打开、保存和导出；耗时像素任务进入后台并显示状态，普通画布拖动和 OpenShop 基础工具不应被自动保存持续阻塞。

## 21. 安全

- OpenShop 和全部运行依赖固定版本、本地托管并执行许可证与漏洞审查。
- 工作区使用严格 CSP，禁止任意远程脚本和未授权网络请求。
- 图片、PSD、字体和项目包验证 MIME、签名、大小、尺寸、解压路径和资源数量。
- 防止路径穿越、压缩炸弹、异常超大画布和恶意字体导致宿主崩溃。
- API 密钥只存在 HstarA 服务层，日志、项目、消息和导出文件均脱敏。
- 上游升级在隔离分支中完成，通过汉化、协议、项目迁移和黄金样例测试后才能合入。

## 24. 总体验收标准

功能在满足以下条件时视为完成：

1. OpenShop 全部用户可见界面完成简体中文汉化，Photoshop 通用概念使用一致的中文版术语，无乱码。
2. 普通画布和智能画布均可创建“图文分层”节点并进入 HstarA 内部全屏编辑器。
3. 同一画布的多个节点、不同画布节点和复制节点的数据完全隔离，重启后可分别恢复。
4. 多个上游图片节点按稳定接入顺序转为图层，来源更新和断线不会破坏已编辑内容。
5. 保存会更新节点预览，“发送到画布”会创建并连接新的普通图片节点。
6. 文字提取和去除文字是两个独立按钮与独立任务，前者创建可编辑文字层，后者创建无字像素层。
7. 生成式填充和局部重绘将结果创建为原坐标局部透明图层，并保留蒙版和生成参数。
8. AI 生成图层不会覆盖现有图层。
9. 每项 AI 功能都有 API/模型选择按钮，并与 HstarA 全局 API 配置、实时模型和真实后台请求保持一致。
10. API 失败、取消、关闭编辑器和删除节点均有明确终态，不残留无限进度或串入其他项目。
11. 中文、英文和中英混排能够编辑和导出，无乱码；缺失字体有明确提示。
12. PNG、JPEG、WebP、原生项目和 PSD 均通过对应黄金样例；PSD 在 Photoshop 中完成图层和文字可编辑性验证。
13. 4096 x 4096、10 图层基线能够稳定打开、保存和导出，关闭项目后临时资源得到释放。
14. OpenShop 与全部依赖包含在工程和 Windows 安装包中，基础编辑断网可用。
15. 上游许可证、版本记录、安全校验和项目迁移机制完整。
