# HstarA PaddleOCR 可选模块设计

## 1. 目标

为 OpenShop 文字提取增加完全本地的 PaddleOCR 识别入口，同时保留现有图像识别 API 和模型选择逻辑。PaddleOCR、Python 运行时和模型不进入 HstarA 安装包，而是由用户从软件设置中按需下载到默认缓存目录或自选目录。

本设计必须满足以下边界：

- HstarA 主程序不导入 PaddleOCR 或 PaddlePaddle。
- 本地 OCR 模块缺失、损坏、崩溃或被删除时，HstarA 和 API 识别仍能正常运行。
- 用户主动卸载模块时，不删除任何画布、图文分层节点、项目素材、识别结果或文本图层。
- 本地 OCR 结果与 API 结果使用同一个 `OCRLayoutV3` 协议和同一套校对、创建文本图层流程。
- 本地识别不静默回退到付费 API，也不在失败后自动重试。

## 2. 非目标

第一版不包含以下能力：

- 不在 HstarA 安装包中内置 Python、PaddlePaddle、PaddleOCR 或模型权重。
- 不允许在 tiny、small、medium 之间切换，固定使用 `PP-OCRv6_medium`。
- 不负责跨语言翻译；“文字提取”只把图片文字转换为可编辑文本图层。
- 不用 PaddleOCR 替代“艺术字体处理”图像生成。艺术字体处理仍是独立的可选图像模型功能。
- 不承诺 PaddleOCR 直接返回真实字体名称、精确字重、描边或阴影。这些属性由本地视觉分析和现有字体匹配逻辑补充。
- 不让用户选择任意 `python.exe` 后由 HstarA 修改该 Python 环境。

## 3. 方案选择

采用隔离式 Sidecar 模块：

```text
HstarA
  -> 通用本地 OCR 模块客户端
      -> 独立 PaddleOCR 工作进程
          -> PP-OCRv6_medium
      <- OCRLayoutV3 JSON
```

PaddleOCR 使用独立 Python 3.13 运行环境。HstarA 当前 Python 3.14 环境不安装任何 Paddle 依赖。未来 PaddlePaddle 提供稳定的 Windows Python 3.14 二进制包后，只升级模块内部运行时，不修改 HstarA 与 OpenShop 的协议。

浏览器版 PaddleOCR.js 不作为第一版方案，因为它目前主要使用 PP-OCRv5，且隐藏页面中的浏览器任务可能受到限速，不满足 OpenShop 隐藏后任务仍要继续执行的要求。

## 4. 外部模块目录

HstarA 管理的默认目录为：

```text
<HSTAR_DATA_DIR>/modules/PaddleOCR/
```

模块目录结构为：

```text
PaddleOCR/
  module.json
  ownership.json
  runtime/python.exe
  worker/worker.py
  worker/adapter.py
  packages/
  models/PP-OCRv6_medium/
  licenses/
```

`module.json` 至少包含：

- 模块标识和模块版本
- Python、PaddlePaddle、PaddleOCR 和模型版本
- `OCRLayoutV3` 协议版本
- 工作进程入口
- 完整文件清单和 SHA-256
- 模型能力标识

`ownership.json` 只在 HstarA 成功安装的目录中创建，用于记录安装目录、安装时间、清单版本和所有受管文件。它是允许 HstarA 删除模块文件的必要条件，但不是唯一条件；卸载前还必须校验规范化路径、模块标识和安装记录。

用户也可以在软件设置中选择一个已经存在的完整模块根目录。该目录标记为“外部目录”，HstarA 只保存连接路径和执行校验，不获得目录删除权。

## 5. 下载组件与版本清单

HstarA 安装包只包含体积很小的下载清单和通用模块客户端。下载清单锁定：

- Python 3.13 独立运行环境
- PaddlePaddle 官方 Windows 二进制包
- PaddleOCR 官方固定版本
- `PP-OCRv6_medium` 检测和识别模型
- HstarA PaddleOCR 工作进程与适配器
- 开源许可证和归属声明
- 每个文件的官方下载地址、大小和 SHA-256

Python、PaddlePaddle、PaddleOCR 和模型从各自官方发布地址下载；HstarA 工作进程与适配器从 HstarA 自身的可信发布地址下载。两类来源都必须进入固定版本清单并通过 SHA-256 校验。

安装器只从清单允许的 HTTPS 地址下载，不执行远程脚本，不使用系统 `pip`，不修改系统 `PATH`、注册表或全局 Python 环境。清单中的各组件作为一组版本发布，不允许单独升级其中一个组件。

## 6. 软件设置界面

软件设置新增“OCR 本地识别”区域，包含：

- OCR 程序位置
- 选择已有目录按钮
- 独立的“下载 OCR 程序”按钮
- 独立的“卸载并删除 OCR 程序”按钮
- 当前状态、模块版本和模型版本
- 更新、修复和断开操作

“下载 OCR 程序”和“卸载并删除 OCR 程序”必须始终是两个独立控件，不能复用同一个按钮并根据安装状态切换按钮含义。按钮可以根据模块状态启用或禁用，但位置、名称和命令职责保持稳定。受管模块已安装时允许独立执行卸载删除；手动关联的外部目录不启用删除，只显示“断开”操作。

点击“下载 OCR 程序”按钮后：

1. 打开系统文件夹选择器，默认定位到当前 `HSTAR_DATA_DIR/modules`。
2. 用户选择安装父目录，HstarA 在其下创建 `PaddleOCR` 模块目录。
3. 如果目标目录已存在且不是有效的受管模块目录，不覆盖该目录，要求用户改选位置。
4. 弹出安装进度窗口并开始下载。

进度窗口显示：

- 总进度和当前文件进度
- 当前文件名
- 已下载大小和总大小
- 当前速度和预计剩余时间
- 当前阶段：准备、下载运行时、下载依赖、下载模型、校验、安装、连通测试
- 取消操作

网络中断或下载失败后不自动重试。保留校验过的完整文件和可恢复的 `.part` 文件；用户再次点击下载时，服务端支持 HTTP Range 就续传，否则只重新下载当前未完成文件。

## 7. 事务式安装

安装过程只写入目标父目录下的临时目录：

```text
.<PaddleOCR>.installing-<request-id>/
```

流程为：

1. 校验目标位置、可用空间和写权限。
2. 下载并逐文件校验 SHA-256。
3. 解包到临时目录并禁止路径穿越和符号链接逃逸。
4. 执行 Python、PaddlePaddle、PaddleOCR、模型和协议探测。
5. 使用内置小型测试图片执行一次真实 OCR 连通测试。
6. 全部通过后写入 `ownership.json`，再将临时目录切换为正式目录。
7. 保存软件设置并刷新模块状态。

安装失败、校验失败或用户取消时，不替换已有可用模块。未完成目录只能由安装任务清理，不能使用未校验的计算路径执行递归删除。

## 8. 文字提取界面

现有 API 和模型选择框保持不变。执行区域显示两个独立命令：

```text
[OCR 本地识别]  [API 识别]
```

行为规则：

- “OCR 本地识别”只调用已配置并通过校验的本地模块。
- “API 识别”完全保留现有提供商、模型、任务和错误处理逻辑。
- 本地模块不可用时，本地按钮禁用并提供进入软件设置的入口。
- 本地失败时不自动调用 API，避免意外费用。
- 两种识别结果都保留在文字提取窗口，直到用户再次主动执行同类识别。
- 两种结果都可以反复点击“创建文字图层”。

## 9. 本地识别数据流

本地识别使用后端任务，保证用户切换 HstarA 左侧功能或 OpenShop 自动隐藏时任务不中断：

1. OpenShop 将当前像素图层保存为项目内受控素材。
2. HstarA 创建本地 OCR 任务并记录画布、节点、项目和源图层归属。
3. 模块管理器按需启动独立工作进程。
4. 工作进程读取受控输入文件并执行 PP-OCRv6_medium。
5. 模块适配器将 `rec_texts`、`rec_scores` 和 `rec_polys` 转换为 `OCRLayoutV3`。
6. 本地样式分析补充颜色、字号估计、方向、旋转、字距估计和艺术字提示。
7. HstarA 校验完整结果后写入当前图文分层节点的任务记录。
8. OpenShop 显示校对结果并使用现有流程创建文本图层。

图片不会因本地识别发送给外部服务。模块下载本身只访问清单允许的官方文件地址。

## 10. OCRLayoutV3 映射

PaddleOCR 输出映射如下：

| PaddleOCR 字段 | OCRLayoutV3 字段 |
| --- | --- |
| `rec_texts` | `blocks[].text` |
| `rec_scores` | `blocks[].confidence` |
| `rec_polys` | `blocks[].quad` |
| 多边形几何 | `rotation`、`writingMode`、字号初值 |
| 字符内容 | `language`、`script`、`dominantScript` |
| 局部像素分析 | `color`、描边与阴影估计 |
| 本机字体匹配 | `font.familyCandidates`、`weight`、`style` |

坐标必须转换为相对于原始源图尺寸的归一化四点坐标。横排与直排由文字流向和局部几何联合判断，不能用旋转角度代替写字方向。

PaddleOCR 不直接提供精确字体身份。第一版优先保证文字内容、位置、方向和尺度；字体由现有免费商用字体池匹配，无法可靠匹配时继续使用已约定的“阿里巴巴普惠体 3.0”回退逻辑。

## 11. 进程与任务隔离

- 第一次执行本地 OCR 时延迟启动工作进程。
- 工作进程使用固定协议输入输出，不允许导入 HstarA 主程序模块。
- 同一 HstarA 会话内保持工作进程就绪，减少重复加载模型的延迟。
- HstarA 退出、模块断开或卸载时关闭工作进程。
- 工作进程崩溃只将当前任务标记为失败。
- 本地识别失败后不自动重启或重试；下次用户主动执行时再启动新进程。
- 取消任务时终止该识别请求并清理该任务的临时输入，保留已安装模块。

## 12. 状态与错误

模块状态至少包括：

- 未安装
- 正在下载
- 正在校验
- 正在安装
- 已就绪
- 版本不兼容
- 路径失效
- 文件损坏
- 连通测试失败

错误信息必须区分下载失败、磁盘不足、权限不足、校验失败、模型缺失、运行时不兼容、工作进程崩溃和 OCR 无可靠结果。错误中不得显示用户目录之外的内部敏感信息，也不得包含 API 密钥。

## 13. 路径变更与卸载

保存新路径前先执行完整模块探测。新目录验证失败时保留旧配置和旧模块连接。

卸载规则：

- 有活动本地 OCR 任务时，先要求取消任务或等待任务结束。
- “卸载并删除 OCR 程序”使用独立确认窗口，明确显示将删除的受管模块路径和预计释放空间。
- HstarA 只允许删除由自身安装、带有效 `ownership.json`、模块标识匹配且规范化路径不是磁盘根目录、用户目录或缓存根目录的模块。
- 外部目录只允许“断开”，不提供递归删除。
- 卸载只删除受管模块目录及其安装临时文件，不删除上级目录。
- 卸载后清除软件设置中的本地模块路径并禁用本地识别按钮。
- 已有 OCR 任务结果和文本图层已经写入项目文件，卸载模块后仍可查看和编辑。

## 14. 安全与许可

- 所有下载必须使用 HTTPS 和固定 SHA-256。
- 解包必须拒绝绝对路径、`..` 路径穿越、设备路径和逃逸链接。
- 工作进程只接受 HstarA 创建的任务文件和允许的参数。
- 本地模块不接收或读取任何 API 密钥。
- 模块附带 PaddleOCR、PaddlePaddle、Python 和其他依赖的许可证与归属文件。
- PaddleOCR 项目采用 Apache 2.0 许可证；发布清单仍需逐项保留所有第三方依赖声明。

## 15. 测试与验收

自动化测试包括：

- HstarA 在完全没有 PaddleOCR 模块时正常启动，API 识别正常。
- 下载清单版本、来源和 SHA-256 校验。
- 安装路径穿越、磁盘根目录和非受管目录删除保护。
- 下载进度、取消、断点续传和失败恢复。
- 临时目录安装成功后才切换正式目录。
- 有效模块、缺文件、损坏文件和版本不兼容探测。
- 工作进程启动、超时、崩溃、取消和下次手动重启。
- PaddleOCR 输出到 `OCRLayoutV3` 的坐标、置信度、横排和直排映射。
- OpenShop 本地 OCR 与 API OCR 使用相同校对和文本图层创建流程。
- OpenShop 隐藏后，本地任务继续执行并可在返回后恢复结果。
- 本地失败不触发 API 请求。
- 下载按钮和卸载删除按钮始终是两个职责独立的控件。
- 外部目录只能断开，受管模块只能删除自身目录。
- 卸载后现有画布、节点、源图和文本图层保持不变。

真实验收样例至少包含：

- 简体中文横排
- 简体中文直排
- 中英文混排
- 旋转横排文字
- 小字号与低对比度文字
- 多文本块排版
- 艺术字体文字内容识别

验收以文字内容、四点位置、横竖方向、文本图层可编辑性和任务持久化为主要指标。艺术字体外观重建仍由独立的“艺术字体处理”功能负责。

## 16. 发布策略

第一版固定使用 `PP-OCRv6_medium` 和一组经过真实 Windows 验证的依赖版本。HstarA 安装包发布通用模块接口、界面和下载清单，不发布大型 OCR 数据包。

模块升级采用新清单和完整兼容性测试，不进行运行时内的单包滚动升级。升级失败时继续使用旧模块。新版本验证成功后再替换旧版本，并在安全完成后清理旧模块文件。
