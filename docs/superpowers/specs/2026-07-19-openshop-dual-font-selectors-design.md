# OpenShop 双字体候选框设计

## 目标

在 OpenShop 文字属性面板中，将单一字体候选框拆为上下两个独立入口：

- 上方为“中文字体”，仅选择简体中文和繁体中文字体。
- 下方为“英文及其他语言字体”，选择英文、日文、韩文及其他非中文字体。

两个入口都沿用现有文字属性应用逻辑，可作用于整个文字对象、编辑中的选区或插入点后续输入。

## 分类规则

- 中文字体：`languageGroup` 以 `zh` 开头，包括 `zh-hans`、`zh-hant`，以及服务端标记为 `01免`、`02免` 的字体。
- 英文及其他语言字体：所有非中文字体，包括 `03免` 字体和未标记免费商用分类的英文或其他语言字体。
- 字体只进入一个候选框，不重复显示。

## 交互

- 两个字体入口纵向排列在文字面板顶部，保持现有控件高度、边框和间距。
- 当前字体属于某一分类时，对应入口显示字体名称；另一入口显示“选择字体”。
- 点击任一入口时，打开现有虚拟滚动字体弹窗，并只渲染该入口对应分类的目录行。
- 同一时间只允许一个字体弹窗打开；点击外部、按 Escape、选择字体或刷新目录时关闭。
- 选择字体后，沿用当前字型解析、选区样式、历史记录和顶部工具栏同步逻辑。

## 实现边界

- 复用一个字体目录缓存、一个虚拟滚动渲染器和一套键盘导航状态，不创建两份完整字体 DOM。
- 为两个入口提供独立触发器和显示值，但不复制字体加载请求。
- 字体目录刷新后，两个入口及当前打开的分类列表同时更新。
- 不修改服务端字体分类、字体安装规则或 `01免/02免/03免` 名称。

## 验证

- 单元测试覆盖两个入口存在、分类互斥、当前值显示、点击分类过滤、字体应用、外部关闭和目录刷新。
- 端到端测试验证文字面板的上下布局、中文和非中文字体选择，以及大字体目录下的虚拟滚动性能。
- 视觉检查确认控件无重叠、面板滚动正常、下方字型和字号控件位置稳定。
